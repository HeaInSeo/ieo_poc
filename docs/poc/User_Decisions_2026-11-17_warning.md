# 사용자 결정 2026-11-17 · 한도 경고(allowed_warning)와 실제 사용 거부의 구분

02-05 단계 8의 R1(`s8-r1`, 2026-11-17 21:19 KST)이 실행 가드에 의해 멈췄다. 공급자 rate-limit 사건의 상태가 `allowed_warning`(7일 창 사용률 0.86, 경고 기준 0.75 초과)이었고, 추가 사용은 `overageStatus: rejected`(out_of_credits), `isUsingOverage: false`였다. 당시 가드는 `allowed`가 아닌 상태를 모두 비허용 한도 신호로 보아 회차를 멈췄고, 사용량은 미계측(관측 하한 billable 1,429, cache_read 3,223)으로 남았다. 사용자는 선택지 (가) 단계 8 종료, (나) 초기화 뒤 재개, (다) 규칙 보완 중 **(다)**를 골랐다.

## 1. 사용자 지시(원문 요지)

1. **경고 허용 조건.** 구독 상태가 `allowed` 또는 `allowed_warning`이고, 추가 사용이 `overageStatus: rejected`이며 `isUsingOverage: false`임이 **모두** 확인될 때만 진행한다. `allowed_warning`은 경고로 기록하고 알린다. 실제 구독 사용 거부(`status: rejected`), 추가 유료 사용 허용·발생, 필수 정보 누락·모순·미확인 상태는 계속 중단한다. 여러 한도 신호 중 하나라도 중단 조건이면 경고 신호가 이를 덮어쓰지 못한다. 기존 시간·토큰·회차 상한과 추가 청구 USD 0은 유지한다.
2. **전체 경로 일관성.** 실행 가드, 사전 관측 검사, 공유 예산 검사, 회차 후 검사, 상태 표시, 실행 문서에 같은 판정을 적용한다. 같은 경고를 다른 단계가 다시 거부하는 불일치가 없게 한다. 관측 자료의 기존 유효 기간(7일)은 유지한다. 공식 문서의 상태 정의와 CLI 2.1.322가 실제로 남긴 R1 로그를 근거로 삼고, 변경 전후 정책을 명시한다.
3. **새 실제 호출 없이 검증.** 기존 로그 재생과 가짜 런타임으로: 추가 사용이 차단된 `allowed_warning`은 경고를 기록하며 정상 진행; 이후 실제 거부·추가 사용·필수 정보 누락이 나타나면 중단; 정상 완료 회차는 계측되고 가드가 중단한 회차는 기존 규칙대로 미계측; 미계측 회차가 다음 호출을 막는 규칙 유지.
4. **R1 기록 보존과 대조.** `s8-r1`은 당시 정책에 따라 중단된 기록으로 보존한다. 실패·사용량·회차 수를 삭제하거나 초기화하지 않는다. 보존된 stream·transcript로 최종 사용량을 정확히 복구할 수 있는지 조사한다. 관측 하한을 정확한 총사용량으로 간주하지 않는다. 근거가 부족하면 미계측을 유지하고 필요한 정산 결정을 구체적으로 제안한다. 정정이 승인돼도 원본을 보존하고 추가 기록으로 남긴다.
5. **재개안.** 교정 PR의 독립 검토·승인 head 병합·main CI 확인까지 진행한 뒤 한 번에 검토할 재개안을 낸다: R1 정산 근거와 남은 예산, 기존 실패 회차를 포함한 회차 집계와 재실행 분류, R1 대체 실행·R2·G1에 필요한 승인, 중앙 체크포인트 대조와 공식 복구 필요 여부, 적용할 코드 SHA와 배포·재시작·허용 규칙 변경 범위, 관측 유효 기간과 재실행 전제. 이번 R1을 기존 예비 회차로 자동 처리하지 않는다. 예산·예비 사용 조건 변경이 필요하면 명시적으로 제안한다.
6. **보고.** 실제 확인된 전달·인수·첫 행동 연결과 도구 제한, 경고로 인한 중단, 미계측 사용량, 미실행 R2·G1을 구분해 남긴다. 정책 교정 완료와 실제 재시험 완료를 별도로 기록한다.
