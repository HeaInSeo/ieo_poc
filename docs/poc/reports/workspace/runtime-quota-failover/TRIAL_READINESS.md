## 단일 승인 묶음에 넣을 증거

1. 실제 역할별 구독 계정과 조직·워크스페이스, quota group, 공급자 인증 방식, 허용 모델을 고정한다. 인증 프로필 및 정책 다이제스트는 기록하되 토큰과 UID의 비밀 매핑은 보관하지 않는다. API 키 대체 경로를 제거한다.
2. 두 역할에서 같은 읽기 전용 저장소·도구 범위를 집행한다. 작업공간 쓰기·외부 파일 접근·셸·MCP·배포 자격·일반 외부 통신을 거부한다. 실제 공급자 인증 및 호출에 필요한 네트워크 목적지만 런타임별로 허용한다. 두 실행 경계의 무해한 접근 시험과 인증 계정 결합을 증거로 첨부한다.
3. 구속된 Claude 계정의 자연 소진 시 운영자 `/usage` 근거를 남긴다. 계정, 실제 할당에 적용되는 기간, 소진, 재설정, 관측 UTC와 확인자, 크레딧 꺼짐을 기록한다. 관측 방식은 수동으로 명시한다. Codex의 동일 시험 역할 로그인에서 App Server `account/read` 및 `account/rateLimits/read`를 사용해 적용 버킷·기간·재설정·가용성을 새로 확인한다. Usage & Billing 또는 관리자 정책으로 크레딧 사용·자동 충전·유료 대체 차단도 확인한다. 과거 조회나 잔액만 있으면 `UNKNOWN`이다.
4. 승인 요청 시 repo/branch/head, 배정·검토 세대, 정책 다이제스트, 체크포인트와 선행 전송 ID, 예산 및 증거 시각을 함께 제출한다. 전송 직전에 동일 조건을 다시 읽고 차이가 있거나 관측한 기간이 끝났으면 중단한다.
5. Claude 전송 0회, Codex 전송 최대 1회, 정지 유예 포함 120초, 과금 토큰 4,000, 캐시 읽기 20,000, 추가 USD 0. 코디네이터가 완료 단계·선행 시도와 실제 저장소 효과를 대조한 뒤 공유 잠금 아래 예산을 확보하고 전송 ID를 기록한다. 다음 미완료 단계만 보내고 같은 ID로 실제 사용량과 종료를 대조해야 통과다. 수락·효과·사용량·권한·과금이 불확실하거나 임계값에 걸리면 추가 전송과 재시도를 중단한다.

별도 검증 항목은 지원되는 최신 Claude 신호를 이용한 무인 소진 감지, 양쪽 자연 소진 시 전송 0건, 한쪽 자연 회복 뒤 권한·예산·체크포인트를 다시 검증한 단일 재개다. 첫 시험은 운영자 관측을 입력으로 하는 단방향 시험으로 기록한다.
