## Admission interpretation

Resolve all applicable windows for the exact selected model and account binding before classifying headroom. Treat an explicit included-limit exhaustion or a fully used applicable window as exhausted only where the provider semantics agree. An absent bucket/window, stale or future timestamp, reset time that has passed without fresh evidence, unknown reached reason, or unmatched account does not provide dispatch authority. Reset time alone never establishes recovery. Attach explicit zero-extra-charge evidence, separate from quota, to any availability claim. A future Codex reader should preserve all applicable bucket and window identities, use a monotonic observation watermark, and retain the App Server protocol/version. A Claude operator check is a manual route, while unattended Claude switching remains blocked.
