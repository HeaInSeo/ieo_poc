# 작업 결과 보고 · TEMPLATE

이 파일은 양식이다. 실제 결과로 집계하지 않는다.

| 필드 | 작성할 내용 |
| --- | --- |
| 계획·작업·회차 | plan_version, task_id, run_id, revision, 이전 보고 참조 |
| 담당·단계·관측 시각 | 실제 주체/역할, 단계, 시작/종료/관측 시각(시간대 포함) |
| 목표·수용 기준 | 명세/프로파일 버전과 검증할 요구·독립 기대값 |
| 만든 산출물 | 코드/문서 경로·PR·커밋 SHA·이미지 digest 등 해당 범위 |
| 검증 방법·실측 | 명령·환경·입력·실제 결과·통과/실패/건너뜀·분모·원본 링크 |
| 판정·검수 | 결과 PASS/FAIL/INCONCLUSIVE와 독립 검수의 상태/주체/증거를 구분 |
| 비용 | 시간·개발/검토/부모/자식 토큰·사람 개입, 미계측 이유 |
| 남은 일 | 문제·영향·다음 행동/담당·재개 조건·추가 실험/대안·누적 상한 |
| 보고 상태 | 원장 snapshot·인덱스 갱신·대화 전달 pending/sent/unknown |

평가/실패/판정 불가이면 채택/보류/기각과 근거·필수 기능 미충족을 덧붙인다. 완료 주장을 독립 검수 완료로 쓰지 않는다.

진행 상태는 state.json만 갱신하고 화면은 생성한다. 이 회차 보고는 불변 증거 참조다. P26이면 REVIEW_PENDING으로 개발이 쉰 시간과 한도로 인한 정지 건수·시간/영향 작업을 별도로 남기며 최초 N건을 보존한다.

역할별 운영 보고는 actor={role,name}·report_type과 공통 5부 구성을 따른다. 일정에는 원 기한/미확정·정상/지연 위험/지연·잔여 작업·지연 사유/영향·실측 근거 예상 범위 또는 미산정을 기록한다. 이 작업/실험 회차 양식은 ProgressReport_v0.schema.json의 운영 사건과 별도이며 연결 ID/원본을 보존한다.
