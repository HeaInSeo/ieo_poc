최종 평가 자료를 보고 수정하면 새 자료/회차로 구분한다. 같은 원본 결과를 여러 보고에 연결해 비용/완료 수를 중복하지 않는다.

진행 상태는 state.json만 갱신하고 화면은 생성한다. 이 회차 보고는 불변 증거 참조다. P26이면 REVIEW_PENDING으로 개발이 쉰 시간과 한도로 인한 정지 건수·시간/영향 작업을 별도로 남기며 최초 N건을 보존한다.

역할별 운영 보고는 actor={role,name}·report_type과 공통 5부 구성을 따른다. 일정에는 원 기한/미확정·정상/지연 위험/지연·잔여 작업·지연 사유/영향·실측 근거 예상 범위 또는 미산정을 기록한다. 이 작업/실험 회차 양식은 ProgressReport_v0.schema.json의 운영 사건과 별도이며 연결 ID/원본을 보존한다.

P36은 작성 3건의 시간/거부/자가 교정/재질문과 결정 시나리오 12건 이상의 시간/일치/재열람/질문/양방향 오인/불편을 남긴다. 합성/실제·형식 revision·사전 기준·참가자 한계·원 시도/재시험을 구분하고 봉인 정답을 사용자 평가 전에 공개하지 않는다.
