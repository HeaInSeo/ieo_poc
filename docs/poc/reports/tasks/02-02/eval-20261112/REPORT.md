**실패 V-22(validation).** “이 문자열들은 증거 어디에도 없어야 한다” 목록의 셋째 문자열(가짜 `sk-ant-…` 토큰의 꼬리)이 `record.json`의 argv에서 발견됐다. 독립 담당은 이를 **사례 작성 오류(scorer-suspect)**로 분류했다: 토큰이 argv에 그대로 나오지 않게 셸 스크립트에서 `"sk-""ant-…"`처럼 나눠 썼으므로 argv 안의 꼬리는 `sk-ant-` 형태가 아니고, 규칙상 가릴 대상이 아니다. 같은 사례의 다른 필드(가림 횟수 3·2·2, 비밀 값 관측, 표식, 판정, 종료 코드)는 모두 통과했다. 별도 표시한 진단 1회(다른 값, 같은 형태)에서 비밀 값·그 SHA는 어느 파일에도 없고 stderr의 실제 토큰은 `sk-ant-[MASKED]`로 가려졌다. **동결 채점기·세트는 고치지 않았고 재채점하지 않았다.** 공식 결과는 33/34이며, 이 실패를 후보 결함이 아닌 기대값 오류로 볼지는 독립 검토가 확인한다.

**누출 검사.** (a) 통과: 91개 검색어 중 후보 소스·저장소에 나온 것은 승인 입력에서 재사용한 표식 2개(`WRITE_DENIED`, `ECHO-OK`)와 01-04 stream UUID 안의 우연한 조각 1개뿐이다. (b) 통과: 후보 커밋 13:40:27Z < manifest 작성 13:53:52Z < 동결 커밋 13:54:14Z < 평가 시작 13:55:01Z. (c) 통과(주석): manifest는 경로·digest·수·계열 이름만 담고, 계열 이름은 다루는 동작 범주만 드러낸다. **이 검사들은 같은 계정의 열람 가능성을 막지 못한다**(개발 계정의 정답 접근 차단은 미검증).
