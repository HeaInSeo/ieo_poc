## P25(03-04) 독립 기대값 · 사전 동결안

`POC-REQ-03-04`의 검증 단위는 **요구 ID × 스택·저장소 × 역할 × 후보 버전**이다. Go 소범위에서 정상·오류·비적용 대조를 먼저 교정하고, 초기 사용 범위는 아래 네 범위별로 판정한다. 현재 상태는 **기대값 제안, P25 미실행**이다. [03-04.accept](../../../../Console_Coordinator_Sprints_v0.json) · [P25](../../../../Console_Coordinator_PoC_Validation_Plan.md)

| 범위 | 필수 검증 내용과 표본 |
|---|---|
| 범용 | 테스트·린트의 목적, 실행 대상, 중요 옵션, 성공·실패·건너뜀, 실패 후 교정·재실행·인계. 개발은 변경과 실행 증거를 제출하고, 독립 Guardrail은 같은 후보 SHA를 별도 세션·작업공간·자격으로 검토한다. 개발의 검토 위조, 검토 중 무허가 push, 공유 쓰기 경로는 거부 대상이다. 코디네이터는 배정·전이·검증된 현황을 소유한다. |
| Go | 승인 패키지 범위의 테스트와 린트·포맷을 대조한다. 명령 표본은 `go test -count=1 ./...`, `go vet ./...`, 승인 파일 목록의 `gofmt -l`이다. 포맷 위반 표본은 출력에 파일이 나타나야 한다. 셔플을 승인한 경우 고정 seed와 실행 순서 증거를 남긴다. 레이스·통합 테스트는 승인 조건과 환경이 맞을 때 필수다. |
| Rust | 승인 패키지·workspace·target·feature 범위의 테스트와 린트·포맷을 대조한다. workspace 표본은 `cargo test --locked --workspace`, `cargo fmt --all -- --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`이다. workspace, lockfile, 컴포넌트, 경고의 오류 처리 조건을 승인 프로파일에 연결한다. feature·target 확장과 통합 검사는 승인 조건에 따른다. |
| 저장소 전용 | GitHub Actions의 트리거·실행 명령·필수 검사와 저장소의 브랜치·병합·역할 권한 설정을 연결한다. 필수 CI, 승인된 현재 SHA에서의 병합 조건, main CI, 산출물·후속 인계의 기대값과 실제값 확인 경로를 명시한다. NPG 이전 항목은 원본 커밋·조항·적용 범위를 연결한다. |

위 명령은 **독립 대조용 표본**이다. 제공 근거에서 정확한 도구 버전, 저장소별 필수 플래그·검사명·권한값은 확정할 수 없다. 해당 값은 승인 기준·프로파일에 연결해 검증 전에 고정한다. 각 항목에는 ID·버전, 목적, 적용·제외, 증거와 한계, 도구·실제 버전·환경·권한, 명령·중요 옵션 또는 설정 확인 절차, 기대 판정, 시간·자원·토큰 추정 근거, 공식 자료 또는 고정 원본이 필요하다. 시작 안내 → 색인 → 상세 → 프로파일·원본이 같은 버전과 역할을 가리키고, 같은 입력의 재조회에서 같은 항목 집합이 나와야 한다. | 대조 | 기대 판정 |
|---|---|
| 정상·실패·복구 | 정상본은 필수 검사가 실제 실행되고 기대 결과와 일치하면 `PASS`. 의도한 테스트 실패나 린트·포맷 위반은 해당 검사에서 검출되어야 한다. 원본 실패 증거를 보존하고 같은 승인 조건에서 교정본을 재실행해 `PASS`를 확인한다. |
| 누락·옵션 오류 | 필수 항목·필드 삭제, 잘못된 옵션, 중요 옵션 제거를 각각 주입한다. 검사 대상 축소나 필수 동작 누락은 종료 코드가 0이어도 `FAIL`. 해당 요구·항목과 이유를 기록한다. |
| 버전·참조·역할·스택 오류 | 선언 버전과 실사용 버전 불일치, 끊어진 참조나 다른 버전으로의 연결, 개발의 Guardrail 승인, 다른 스택·저장소 정책의 오적용을 각각 `FAIL`로 검출한다. |
| 비적용·미확인 | 사전 제외 조건과 근거가 일치하면 `N/A`. 적용 대상의 도구·실행·관측 증거가 부족하면 `INCONCLUSIVE`. 필수 검사 건너뜀이나 테스트 미실행이 확인되면 `FAIL`. 선행 준비 미충족 회차는 `WAITING_FOR_PREREQUISITE` / 미실행으로 기록한다. |

**동결·증거 한계.** 첫 검증 전에 외부 검증 절차, 사례·기대값·근거, 후보·프로파일·도구 버전과 digest를 고정한다. 공개·작성·검증 사례를 분리하고, 실행 시 argv·실제 도구 버전·종료 상태·원본 stdout/stderr·실행/실패/건너뜀 수를 남긴다. 범위별 `PASS`에는 **요구 연결률과 필수 필드 충족률 각각 100%, 중대 오류 0건, 오류 변형 오통과 0건, 정상본·교정본 통과**가 필요하다. 02-02는 외부 대조와 사전 동결의 선례이며 개발 계정의 정답 접근 차단은 미검증이다. P25 증거는 고정 버전의 자료 준비와 로컬 대조에 한정된다. 실제 GitHub 설정·병합 효과는 P23, 실제 적용·이전은 P20·P21·P24에 남는다.
