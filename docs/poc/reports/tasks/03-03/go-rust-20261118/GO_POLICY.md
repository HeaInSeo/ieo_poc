# CAT-GO@0.2.0 · Go 검사 정책과 실행 예

`POC-REQ-03-03 / poc-acceptance-v1.3.3@4 / 03-03.accept`. [작성 계약](../../03-01/catalog-contract-20261118/CATALOG_CONTRACT.md)의 Go 항목과 [03-02 공통 기준](../../03-02/common-policy-20261118/COMMON_POLICY.md)을 구체화한다. 작업에 Go 모듈이 포함될 때 적용한다. 순서·레이스 검사의 필수 여부는 변경 범위와 사전에 승인한 프로파일로 확정한다.

격리 예는 **Go 1.26.10 linux/amd64**와 레이스 검사용 **GCC 8**을 사용했다. 표준 라이브러리만 가져오는 모듈을 확인했고, 대상 저장소에 적용할 때는 해당 모듈의 Go·플랫폼·cgo·빌드 태그·외부 서비스·의존성 잠금을 기록한다. 개발 계정이나 생산 데이터는 제공하지 않는다.

| 검사 | 고정 예시와 중요 옵션 | 기대 결과와 한계 |
| --- | --- | --- |
| 형식 | `gofmt -l .`로 스코프의 파일명 목록을 얻는다. 출력이 비어야 통과다. | 포맷 차이는 결과 목록으로 확인한다. 명령 자체는 차이가 있어도 0일 수 있어 빈 목록을 별도로 검사한다. 자동 쓰기 모드는 후보를 수정하는 별도 동작이다. |
| 린트 | 모듈에서 `go vet -mod=readonly ./...` | 샘플의 잘못된 형식 문자열 등을 찾는다. 승인 대상 분석기의 실제 진단과 비0 종료를 보존한다. 의미 정확성·동시성 전체를 판단하는 근거는 제한적이다. |
| 기능 | `go test -mod=readonly -count=1 -json ./...` | `-count=1`은 테스트 결과 캐시 재사용을 막고 `-json`은 패키지·개별 테스트 이벤트를 남긴다. 승인된 필수 테스트의 실제 `pass`와 패키지 결과를 확인한다. |
| 순서 의존 | P20과 같이 승인 범위에서 `go test -mod=readonly -count=1 -shuffle=<고정 seed> -v ./...` | seed와 도구 버전을 보존한다. 일반 순서 성공만으로 필수 셔플을 충족하지 않는다. 관측한 seed는 다른 seed·패키지 조합의 검증까지 대표하지 않는다. |
| 레이스 | 지원 대상에서 `go test -mod=readonly -race -count=1 ./...` | `-race`가 활성화된 빌드와 지원 플랫폼·cgo/C 컴파일러를 기록한다. 실행된 경로의 관측이다. 필수 환경이 없거나 인자가 빠진 회차는 보류한다. |

`-mod=readonly`를 사용하며 외부 의존성을 쓰는 저장소는 검사 전후 `go.mod`·`go.sum`의 변화도 대조한다. 예행은 로컬 도구와 별도 빈 캐시를 사용하고 네트워크·자동 툴체인 전환을 차단했다.

실제 결함·설정 위반과 확인된 비0 종료는 FAIL이다. 프로파일의 필수 테스트가 `skip`·미관측이거나 실행 범위에서 빠지면 INCONCLUSIVE로 남기고 요구 충족을 보류한다. 비적용은 승인된 제외 조건을 충족할 때만 사유와 함께 기록한다. 이 예의 내부 실패 사례는 기대한 진단과 종료 코드가 모두 일치할 때 대조 시험 PASS다. [격리 실행 기록](evidence/isolation.txt)의 명령별 wall time과 peak RSS를 비용 비교 기준으로 사용할 수 있다. 최초 stdlib 빌드·레이스 빌드는 같은 총괄 회차 내의 캐시 재사용과 구분한다. 이 값은 두 표준 라이브러리 모듈의 관측이다. 다른 모듈의 자원·시간은 별도 실측 전 미산정이다. 모델 요청은 0회다.
