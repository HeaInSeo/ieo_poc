## 판정 대조

| 사례 | 기대 |
| --- | --- |
| 정상 Go | 포맷 결과 비어 있음, vet 성공, 실제 필수 테스트 pass 이벤트, 레이스 검사 성공 |
| Go 오류·건너뜀 | 형식 차이·vet 진단·단언 오류의 비정상 종료. 필수 skip은 패키지 종료가 0이어도 통과 증거 부족 |
| Go 순서 의존 | 일반 순서 통과, 고정 셔플에서 실패, 같은 seed와 독립 상태로 교정하면 통과 |
| 정상 Rust | 동일 버전에서 형식·Clippy·단언 대조 통과, 필수 단위 시험 1건 실행 |
| Rust 오류·건너뜀 | 형식 차이·Clippy 경고·단언 오류 각각 검출. 필수 ignored는 종료 0이지만 통과 증거 부족 |

## 관측 결과와 비용

표적 대조 **18/18**. Go의 일반 순서는 통과했고, `-shuffle=2`에서는 공유 상태 의존을 재현했다. 같은 seed에서 테스트별로 큐를 준비하도록 교정한 뒤 통과했다. 필수 Go `skip`과 Rust `ignored`는 명령 자체가 0을 반환했지만, 실제 필수 시험의 성공이 빠져 통과 증거로 사용할 수 없다. 도구 진단과 단언 오류는 기대한 코드와 메시지를 반환했다.

| 범위 | 사례 | 명령별 wall time 합계(초) | 명령별 peak RSS 최대(KiB) |
| --- | --- | --- | --- |
| GO | 11 | 26.48 | 282568 |
| RUST | 7 | 0.57 | 152044 |

첫 명령에서 캐시가 비어 있었고 이후에는 같은 회차의 캐시를 썼다. 종료 시 cache·target·로그를 포함한 scratch는 130380 KiB였다. 합계는 검사 명령의 wall time이며 동시 자원 합이나 제품 레포 전체 비용은 미산정이다. 최초 예행에서 링커 경로가 누락된 것을 확인해 링커 파일만 읽기 전용으로 제공했다. seed 1은 이 버전에서 순서를 뒤집지 않았으므로 관측된 seed 2를 고정했다.

## 재현

`bash run-isolated.sh <Go 1.26.10 디렉터리> <Rust 1.99.1 디렉터리> <빈 작업 디렉터리>`를 사용한다. [실행기](run-isolated.sh)와 [사례](verify-cases.sh)는 읽기 전용, 빌드·캐시·산출물은 회차별 scratch에 둔다. 상속 환경을 초기화하고 네트워크·PID를 분리했으며 로컬 도구와 링커만 제공했다. 두 테스트 모듈은 외부 패키지를 사용하지 않는다. 각 검사에는 120초의 예행 한도를 적용했다. [보존 실행 기록](evidence/isolation.txt)

이 사례는 상세 정책의 작성·재현용이다. 제품 워크스페이스 전체, 다른 스택 및 숨긴 평가 입력은 각 후속 작업의 입력·권한·프로파일로 검증한다. 03-04/P25의 독립 검증, P20/P24의 평가 및 07-01 다른 스택 적합성 확인은 후속 범위다. 모델 호출과 운영 변경은 0건이다.

## 첫 독립 사전 검토의 교정
