## OCI 객체 전송량

값의 단위는 바이트다. 내보낸 gzip layer, config와 manifest를 digest 단위로 검산했다. 두 스택 행은 같은 content-addressed 저장소에서 이미 보유한 객체를 한 번만 전송하는 경우다.

| 배치 | 통합 A | 언어별 B |
| --- | ---: | ---: |
| Go만 | 608,169,695 | 377,650,653 |
| Rust만 | 608,169,695 | 540,513,278 |
| 두 스택을 같은 OCI 저장소에 두는 경우 | 608,169,695 | 608,164,020 |

로컬 OCI 내보내기 과정에서 manifest digest가 달라졌다. config SHA와 rootfs diff ID 일치를 검증했고, 새 저장소에 가져온 실행 파일에서 필수 검사를 확인했다. 외부 레지스트리 요청 트래픽과 네트워크 지연은 계측하지 않았다. [객체별 크기·digest](evidence/objects.json) · [내보내기 명령 출력](evidence/oci-export.txt)

## 첫 검증 완료까지 걸린 시간

스택별 두 fixture SHA를 고정하고 새 Podman 저장소와 이미지를 가진 같은 저장소에서 각각 실행했다. 아래 값은 두 관측의 중앙값이다. cold는 로컬 OCI 가져오기부터, warm은 이미지 확인부터 컨테이너 검증 명령이 완료될 때까지 잰다. 빌드 캐시는 각 컨테이너에 새로 제공했다. 호스트 파일 캐시는 초기화하지 않았다. warm 회차의 OCI 가져오기는 0건이다.

| 스택 | 구성 | cold(초) | warm(초) |
| --- | --- | ---: | ---: |
| go | A | 46.46 | 11.92 |
| go | B | 34.67 | 11.19 |
| rust | A | 37.87 | 1.24 |
| rust | B | 31.57 | 1.19 |

필수 검사 16/16이 통과했다. Podman runroot의 길이 제한과 정리 중 overlay 경로 충돌을 표적 시험에서 확인했다. 본 비교에는 짧은 로컬 경로와 해당 시험 이미지 ID를 지정한 정리 방식으로 완료한 회차를 사용했다. [회차별 값과 명령](evidence/readiness.json) · [원본 출력](evidence/raw-streams.tar.gz) · [시험 드라이버](measure-local.py) · [호스트 관측](evidence/environment.txt)

## 갱신 비용

공통 정책은 기존 문서에 주석 한 줄을 추가하고 내장 정책 입력 목록의 해당 해시를 갱신했다. Go 도구 디렉터리에는 합성 표식 파일을 추가했다. 실제 도구 버전·권한·정책 요구사항은 기존 승인 범위로 검사했다. 다섯 개 로컬 변형에서 하위 레이어와 diff ID를 재사용했고 다음 결과를 얻었다.

| 갱신 대조 | 구성 | 변경 이미지 수 | 새 OCI 객체(바이트) | 빌드 합(초) | 필수 검사 합(초) | 확인 스택 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| common | A | 1 | 15,803 | 0.68 | 12.01 | go, rust |
| common | B | 2 | 24,410 | 1.44 | 12.20 | go, rust |

새 바이트는 기존 배포 조합이 공유 그래프에 있는 경우의 새 객체 합이다. 신규 전체 툴체인 배포와 저장소별 외부 프로파일의 개정은 이번 회차의 계측 범위 밖이다. [갱신 결과](evidence/updates-changes.json) · [갱신 이미지와 검산 시간](evidence/updates-images.json) · [갱신 드라이버](measure-updates.py)

## 재현 입력

03-05의 Go·Rust·통합 태그를 로컬에서 `podman save --format oci-dir`로 내보내고, 각각 `go`, `rust`, `combined` 하위 경로에 둔다. 같은 고정 이미지를 읽는 전용 저장소와 빈 출력 경로를 사용한다. 각 도구의 입력 순서는 `measure-local.py OCI_레이아웃_상위_경로 출력`, `measure-updates.py P22-B_저장소 기본_비교_출력 갱신_출력`이다. Python 3.12에서 실행한다.

## 채택 근거

한 노드에서 한 스택만 필요하면 B가 cold 객체량을 줄인다. 한 저장소에서 두 스택을 모두 사용하면 layer 공유로 객체량이 거의 같으며 A는 이미지 한 개를 관리한다. 두 회차의 로컬 시간 및 계측 범위를 근거로 구성별 후보를 유지한다. 독립 검토와 03-08 수용은 대기 중이다. 실제 모델 호출, 추가 청구, 운영 서비스 변경은 모두 0건이다.
