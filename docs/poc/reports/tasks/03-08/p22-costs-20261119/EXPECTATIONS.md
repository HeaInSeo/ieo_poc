# 03-08 전송·준비·갱신 비용 비교 계획

`POC-REQ-03-08 / 03-08.accept / poc-acceptance-v1.3.3@4`. 03-06에서 기능·역할·오류 대조를 통과한 이미지 digest와 프로파일을 그대로 사용한다. A는 통합 이미지 한 개, B는 같은 기반의 Go와 Rust 파생 두 개다. [P22-B 수용](../../03-06/p22-basic-20261119/ACCEPTANCE.md) · [P22-C 계획](../../../../Console_Coordinator_PoC_Validation_Plan.md)

| 측정 | 고정 입력과 판정 |
| --- | --- |
| 전송량 | 승인 이미지에서 내보낸 OCI manifest·config·layer의 크기와 해시를 파일로 확인한다. 이미지별 합과 한 저장소에서 Go·Rust를 연이어 받는 경우의 digest 단위 합집합을 기록한다. 실제 압축 형식과 레지스트리 요청 부가량의 계측 범위를 표시한다. |
| 준비 시간 | 동일한 Go·Rust 예제 SHA와 검증기, UID/GID 20001 및 동일 자원 조건을 사용한다. 초기 이미지 보유 0인 새 로컬 Podman 저장소에서는 OCI 가져오기 시작부터 첫 필수 검사 성공까지 잰다. 동일 저장소의 다음 회차에서는 승인 이미지를 보유한 상태에서 다시 검사한다. OS 파일 캐시·로컬 디스크 영향은 환경으로 기록한다. |
| 갱신 범위 | 공통 정책의 의미에 영향을 주지 않는 시험 표식과 Go 도구 디렉터리의 시험 표식을 각각 새 이미지로 만드는 대조를 별도로 수행한다. 영향받는 배포 단위와 재검증 스택을 정한다. OCI 새 객체만 합산하고, 빌드 시간과 원본의 하위 레이어 재사용 여부를 남긴다. 실제 새 버전의 전체 툴체인 교체와 외부 배포는 후속 범위로 기록한다. |
| 판정 | 각 준비 시간은 필수 검사가 실제로 통과한 회차에서만 비교한다. 두 구성이 동일한 기능을 충족한 범위에서 전송량·소요 시간과 관리할 배포 단위의 차이를 기록한다. 측정 범위 밖 채택은 보류하고 결과를 독립 대조한다. |

저장소와 큰 임시 파일은 별도 `/tmp` 경로를 사용한다. 승인 이미지, 정책, 관련 역할 환경은 읽기 전용으로 재사용한다. 운영 레지스트리, 활성 서비스, 실제 모델 호출을 사용하지 않는다.
