# 08-03 · P09 관측 검증 준비

작업 기준은 `POC-REQ-08-03 / 08-03.accept`다. 다음 실행의 입력과 판정표 초안을 고정한다. [P09 계획](../../../../Console_Coordinator_PoC_Validation_Plan.md) · [08-02 원본](../../08-02/cluster-baseline-20261119/REPORT.md) · [격리 초기화 재현](../../../../../../probes/0802-cluster-baseline/README.md)

## 입력

- 작업 기준 main `3bd07a17040d09a7a6ac4373968f22ace08bdb1b`의 원장에서 08-02와 02-01의 수용을 확인했다. 새 관측 회차는 #109에서 검증한 고정 이미지·차트·격리 Kubernetes 초기화를 재사용한다.
- 회차에 고유한 파일과 TCP 요청 표식을 사용한다. 실행 전에 repo/role, namespace, Pod UID, container ID, 세션·배정 세대, 프로세스 PID·시작 시각·UID의 대응표를 기록한다.
- 시험 구간 전후에 알려진 신호를 생성한다. 관측기 준비 상태, 정책 적용 범위와 사용할 수 있는 손실 지표를 각 구간의 원본으로 남긴다.

## 대조 사례

| 사례 | 기대 판정 | 보존할 근거 |
| --- | --- | --- |
| 개발·Guardrail·제품 Pod의 허용 및 금지 비교 대상 TCP 시도 | 각 시도 이벤트가 지정된 Pod와 프로세스에 귀속된다. 수신 여부는 수신기 기록으로 대조한다. | 훅 이벤트, 클라이언트 결과, 시험용 수신기 기록 |
| 역할별 알려진 프로세스 실행과 시험 파일 접근 | 알려진 액션과 원본 이벤트의 역할·컨테이너·PID·UID·시작 시각이 대응한다. | 프로세스 입력과 원본, 파일 이벤트, 각 실행의 Pod 기록 |
| 관측기 중단 | 현재 관측이 불충분하다고 판정한다. 통과 0건이다. | 중단 기록, 구간 경계 신호, 가용한 손실 지표 |
| 정책 적용 대상에서 빠진 시험 Pod | 적용 공백을 확인하고 관측 불충분으로 판정한다. 통과 0건이다. | Pod 라벨, 활성 정책과 선택 대상, 구간 원본 |
| 다른 Pod의 이벤트를 현재 요청과 대조 | 다른 Pod의 증거가 현재 역할에 귀속되지 않는다. 통과 0건이다. | 두 Pod의 식별자, 원본 이벤트 및 거부 판정 |

첫 검증은 기존 격리 초기화와 원본 이벤트 수집 경로를 연결한다. 실제 실행 관측과 독립 대조가 완료되면 회차 판정과 증거 경로를 원장에 반영한다.
