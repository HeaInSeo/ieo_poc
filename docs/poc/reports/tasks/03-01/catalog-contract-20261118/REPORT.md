## 산출물과 범위

- [작성 계약](CATALOG_CONTRACT.md)에서 항목 ID·버전, 요구와 수용 기준, 적용·제외 조건, 실행 권한, 증거, 판정과 비용을 고정했다.
- [색인](catalog.json)에 공통·Go·Rust·저장소 전용의 조회 키와 항목 상세를 작성했다. `CAT-FORM@0.1.0`에 이 작업의 수용 항목을 연결했다. 후속 입력 5건은 작성 후보로 표시했다.
- [원본 대응표](sources.json)에서 항목·버전별로 요구·이식 후보·관측을 구분했다. 원본 9개를 기준 커밋, 전체 파일 SHA-256, 줄과 구절로 고정했다. NPG의 보존 자료는 이식 또는 역사적 관측 근거이며, NPG의 기존 Node 22/24 CI는 현재 브랜치 보호나 P21/P23/P25 통과 근거로 사용하지 않는다.

## 03-01 수용 기준 대조

| 기대 | 관측 |
| --- | --- |
| 승인 명세와 T01 요구-수용 연결을 재사용 | 명세와 01-01 범위표의 요구·수용 항목을 찾아 항목 6개 및 제공된 프로파일 rev 4와 대조 |
| 원본 추적이 항목별로 재현 가능 | 버전 조인 6/6, 원본 식별·SHA·고정 커밋 blob·인용 위치 9/9 |
| 필수 필드 누락과 연결 오류를 차단 | 정상 1건과 오류 변형 12건 기대 일치. 누락·잘못된 프로파일·버전 조인·중복·저장소 바인딩·미정의 원본·stale digest·revision·구절 오류·이식 후보의 요구 근거 승격·승인 근거 경로 변조·같은 파일의 다른 조항 인용을 각각 확인 |
| 적용 범위와 증거 의미를 구분 | 범용·Go·Rust·저장소 전용 표본 각 범위 확인. NPG 워크플로는 이식 후보, 기록된 실행은 관측으로 분리 |

[검사기](verify_catalog.py)와 [표적 시험](test_catalog.py)을 이 디렉터리에서 `python3.11 verify_catalog.py`, `python3.11 test_catalog.py`로 재실행할 수 있다. 원본을 대조하려면 기준 커밋의 Git 객체가 필요하다. [관측 로그](verification.txt).

자동 검증은 03-01의 작성 양식·연결 확인이다. 현재 head의 독립 검토와 병합 CI 완료 후 03-02 준비에 사용한다. P25와 후속 명령 시험은 미실행이다.

첫 독립 검토 대상 `38dafe35fc84578981a8809cf0ecff488e452c8b`의 지적 두 건을 교정했다. 승인 출처를 수용 항목별로 고정하고 승격·경로 변형 회귀 시험을 추가했다. 진행 원장의 02-05 활성 조건은 기존 조건부 승인, 실행 직전 확인 및 R1b 마감으로 갱신했다.

두 번째 독립 검토 대상 `c3553cbe5e5b2b7b54ea4eb19b629e585ab7bb8c`의 지적을 교정했다. 승인 출처 ID에 경로뿐 아니라 구간·인용을 결합했다. 같은 명세 파일과 digest를 유지한 채 03-02 조항으로 바꾸는 변형은 거부된다.
