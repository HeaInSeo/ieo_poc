# Daily report archive

REQ-11. An operator-owned, immutable registry for each run maps exact canonical IDs `synthetic-fixture` and `production-probe` to the two private count backends. There are no aliases. Treat any other string as unknown. The source gateway's workload identity is the only principal with network access and authentication credentials accepted by the backends. The publisher has only gateway access, cannot obtain the gateway identity, and has no alternate count backend route. Before any backend call, the gateway applies the allowlist containing only `synthetic-fixture`; it emits a request ID, the canonical source ID for registered sources or the raw identifier for unknown sources, and an allowed or denied disposition for every request to read, including ones denied before dispatch. Abort before dispatch if the attempt cannot be recorded. The publisher may populate the stored count only from the gateway result for the current request. Independently instrument the two backend ingress points; record accepted calls with request and canonical source IDs, without reading the gateway trace. Denied ingress and network probes are observable separately from accepted calls. Independently observe each backend-bound transport send attempt at gateway egress before the transport can drop, deny, or deliver it, with request ID and destination backend. Include failed sends and retries. Gateway decisions are observable independently of this egress collector.

REQ-12. Only the independent Archive Verifier service can confirm verification. The publisher, reader and client cannot write its authoritative records. For this fixture it verifies an archive exactly when it passes the hash-contract schema and its decoded content contains at least one character other than ASCII space. A schema-valid all-space content value is declined with an explicit decision and no evidence record. On approval it proceeds by issuing an authenticated record binding the archive ID, immutable version, and SHA-256 of the canonical submitted content. The publication service recomputes the hash of the bytes it will accept and uses only the Verifier's authenticated record for the exact triple, never a client's `verified` flag or a claimed issuer name. The Verifier signs the exact triple with its private signing key after approval; publication verifies the authenticator against the pinned Verifier public key before accepting that evidence. A missing signature or a signature that does not validate under that key is untrusted even when the issuer label and exact triple match. Missing, untrusted or mismatched evidence yields HTTP 422 before any count-source read or store change. Even with matching evidence, return HTTP 201 only after receiving a valid count from the gateway for this request and committing the complete verified record. If the gateway fails to record the attempt or provides no valid current-request count, return HTTP 503 without writing the store. On attempt-recording failure dispatch zero backend calls. Accept a gateway result only on the trusted gateway response channel for an outstanding publication request. Its JSON object contains exactly request_id and source_id strings and count, a JSON integer literal in the inclusive range 0 through 2147483647 (digits only, with no sign, decimal, exponent or leading zero except for zero itself). Reject duplicate, missing or extra fields. The request_id must equal the active request's ID and source_id must equal synthetic-fixture. Assign a fresh unique ID to every request; a result for a previous or completed request is stale. At the start of the gateway invocation record monotonic time t0. The fixture result deadline is t0 + 1 second on the mock clock. Only the first valid trusted result received strictly before that deadline wins; the deadline wins at equality. Ignore untrusted channel input entirely. While awaiting a result, malformed or mismatched trusted input terminates the request with 503. Silence until deadline also terminates it with 503 and no mutation. Claiming a result or closing a request is atomic per request ID. Once a valid result is claimed, later input cannot replace it even before commit. The deadline applies to result acquisition; it does not interrupt a commit after a result has been claimed. After a failure or completion, late input cannot trigger work or another response. Never reuse a result for another request. A missing, malformed, out-of-range, mismatched or stale gateway result is not a count for this request. If the isolated store rejects the write before commit, roll it back and return HTTP 503.

### REQ-12 shared hash contract

The submitted archive is the `archive` object inside the request envelope. At each service's ordinary request endpoint retain the original archive bytes until strict validation. After authentication and, for publication, authorization, run the strict wire parser directly on the original HTTP body before any object mapping or reserialization. The parser identifies the archive value from the original bytes, checks its complete raw token span, and rejects duplicate keys before they can collapse. A BOM in the archive span is invalid, as is a BOM in the request body. Only after this step can publication look up and authenticate evidence, invoke the gateway or write the store. Both services parse the raw archive object as UTF-8 JSON without BOM, reject invalid UTF-8, duplicate member names, unknown archive fields and missing fields, then validate exactly these three decoded string values: `archive_id` matches `[a-z][a-z0-9-]{0,31}`, `version` matches `[1-9][0-9]{0,8}`, and `content` matches `[A-Za-z0-9. _-]{1,256}` (whole-string ASCII matches). `verified` and evidence are transport metadata outside the archive object and are not hash inputs. The permitted characters require no JSON escaping. Serialize the validated values into the literal template `{"archive_id":"ID","version":"VERSION","content":"CONTENT"}`, replacing the three uppercase placeholders with their decoded values verbatim. Do not trim or normalize field values. Hash the UTF-8 bytes from the first opening brace through the final closing brace inclusive, with no BOM, separator spaces, or trailing newline. The Verifier signs the exact tuple of the decoded archive ID, decoded version, and this SHA-256 after independently confirming verification. The publication service repeats canonicalization over the submitted archive it will persist and matches all three fields to the trusted evidence. Invalid archive encoding or schema is 422 for an authorized publisher before any gateway or store action. Non-publishers are subject to REQ-13 first.

Shared vectors below show the inner object only. The expected bytes strings are literal ASCII, excluding the Markdown backticks. Both services must independently produce the expected bytes and digest for each vector.

- V1 input `{"archive_id":"daily-1","version":"1","content":"daily report"}` → bytes `{"archive_id":"daily-1","version":"1","content":"daily report"}` → SHA-256 `0af55fa7577094b906f881e370f816bfb587563d64f5d5b26de48abe4881ffaa`.
- V2 input `{ "content" : "daily report", "version" : "1", "archive_id" : "daily-1" }` → bytes `{"archive_id":"daily-1","version":"1","content":"daily report"}` → SHA-256 `0af55fa7577094b906f881e370f816bfb587563d64f5d5b26de48abe4881ffaa`.
- V3 input `{"archive_id":"daily-1","version":"1","content":"daily reports"}` → bytes `{"archive_id":"daily-1","version":"1","content":"daily reports"}` → SHA-256 `5803ebb8dd291e476ffcf587f4e053b0de4da4d9378226a5602e65eca5f58774`.

REQ-13. Authenticate first, then require the publisher role before validating archive evidence or reading counts. An authenticated principal lacking publisher receives HTTP 403, regardless of evidence or reader role, with no source reads and no mutation. The reader role only grants reading.

AC-14. Use isolated storage, role fixtures (publisher, reader without publisher, authenticated principal with neither role), the Verifier, and two backend stubs. Both stubs return 42. The first positive request uses V1. Capture that record by archive_id and all persisted fields for the subsequent store comparisons. Assert one allowed gateway attempt and independently exactly one actual egress send and one accepted backend call for that request and source. 2. After each response, assert HTTP 422, no gateway attempts or accepted backend calls, and that the immediate complete store contains only the captured ID and identical persisted fields.
3. Using each of the two non-publisher credentials, submit both a verified and an unverified archive. Assert authentication succeeded and the resolved role set is respectively reader-only or empty. 4. Compare the complete allowed gateway trace, complete independent egress send-attempt trace, and complete independent accepted-ingress trace as multisets of (request ID, canonical source ID). Keep the egress observer active from before the first request until all requests and queued transport work are drained. Include all sends to either backend, even events without a request ID, and fail on any unassociated send. Run the unchanged normal-run checker on copies of the observations with one additional pre-ingress dropped-send event for a rejected request and no corresponding accepted call; require failure. The unmodified observations must pass.

- Shared malformed archive wire vectors. Let B be the literal UTF-8 bytes in V1, excluding Markdown delimiters.
