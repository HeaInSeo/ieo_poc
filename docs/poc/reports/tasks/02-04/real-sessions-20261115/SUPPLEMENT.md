  - 몫이 부모＋자식보다 어느 항목에서도 작지 않다.

**귀속하지 못한 부분과 확인 범위**:
- D4 몫 전체(6,688/1,155/11,393/1,142)는 부모·자식에 귀속되지 않았다. 확인한 범위는 다음과 같다.

  - 자식이 없었다.
  - 압축 사건 1건이 있었다.
  - CLI 회차 합계가 이 몫과 같다.
  - 부모 전사에는 압축 경계·요약 항목만 있고 그 호출의 사용량 기록은 없다.
- 그래서 이 차이가 압축 호출에서 왔을 가능성이 크지만, 호출별 사용량 기록으로 확인하지는 못했다. **전부 압축 비용이라고 단정하지 않는다.**
- D1~D5 몫 합 = D5 누적(§11 항목 7)은 회차 몫이 같은 세션 누적의 연속 차분이라 생기는 검산이다. 귀속 정확성을 독립적으로 입증하지 않는다. 이 검산의 실제 의미는 연쇄의 모든 회차가 측정됐고 빠진 회차가 없다는 것이다.

| --- | --- |
| 목적 | 실제 Claude가 모델 요청을 처리하는 중에 어댑터 `stop`(또는 회차 시간 상한)으로 멈춘다. 다음을 확인한다: 프로세스 그룹 정리(잔류 0), 체크포인트 `after_run`, 사용량 처리(미계측), 다음 reconnect가 같은 세션을 재개하는지 또는 대조를 요구하는지 |
| 대상 역할 | 개발 1회(쓰기 도구가 있어 잔류 위험이 더 큰 쪽). Guardrail은 필요 시 1회 |
| 호출 수 | 정지 회차 1회. 그 뒤 재개 확인 1회. 합 2회(개발) |
| 중단 방법 | 첫 `assistant` 사건을 관측한 뒤 어댑터 `stop`을 보낸다. 대안은 짧은 회차 시간 상한(예: 20초)과 오래 걸리는 프롬프트다 |
| 기대 결과 | 정지는 `Requested`(또는 `RunTimeout`), `cleanup_failed` false, 잔류 프로세스 0. 사용량은 **미계측**(guard가 멈춘 회차의 규칙). 호출자가 `stop_required`로 다음 호출을 막는다 |
| 사용량 미계측 시 예산 차감 | 미계측은 0으로 두지 않는다. 결정 후보는 둘이다. (가) 그 회차 창의 토큰 여유 전체를 상한으로 차감한다. (나) 관측 하한＋세션 누적 증가분(다음 재개 회차의 기준 회차로 쓸 수 없으므로 정정 절차가 필요)으로 차감한다. 이번 D3처럼 사용자 결정과 보존 기록 재평가를 거친다 |
| 후속 재개 조건 | 사용자 결정 → 정정 기록(재평가)·예산 대조 → 재시작 가드 → 재개 회차 |
| 예산 | 04-05의 예산은 아직 승인되지 않았다. 02-04 예비 회차(개발 2·Guardrail 3)를 이 시험에 쓰려면 별도 결정이 필요하다 |
