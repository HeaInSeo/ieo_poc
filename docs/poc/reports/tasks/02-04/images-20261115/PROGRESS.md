## 1. 코디네이터 PID 1

**종료 처리**:
- `ieo-coord serve`가 SIGTERM/SIGINT를 받으면 새 요청을 받지 않고 종료 코드 0으로 끝난다. 일꾼 스레드는 처리 중인 요청을 마친 뒤 대기에서 깨어나 끝나도록 짰지만, **처리 중인 요청을 마치는 동작은 시험하지 않았다.** 신호 처리기가 없는 PID 1은 SIGTERM을 무시해 정지 제한 뒤 강제 종료된다.
- 시험(`tests/shutdown.rs`, 시험 DB): 401 응답으로 동작을 확인하고 SIGTERM을 보내면, 10초 안에 종료 코드 0으로 끝나고 “stopping/stopped”를 남긴 뒤 더 이상 듣지 않는다.

**DB 접속 정보**: `IEO_DB_URL` 외에 `IEO_DB_URL_FILE`(파일 경로)을 받는다. 컨테이너에서는 podman 비밀을 파일로 마운트한다. 처음에 환경 변수형 비밀을 썼더니 `podman inspect`의 환경에 값이 보였다. 그래서 파일형으로 바꿨다. 지금은 inspect·argv·PID 1 환경 어디에도 비밀번호가 없다(시험 기록).

**기동 검사**(X-01 이월 U3):
- repo 바인딩의 `sprint_id`가 이미 Notion 가져오기가 가진 시험 ID이면 기동을 거부한다(종료 코드 2, “binding sprint_id owned by a Notion import (repo: id)”). 변환 경로가 가져오기 소유 스프린트에 쓰는 길을 기동 때 막는다.
- 시험: 충돌하면 거부, 충돌하지 않으면 기동.

**repo 범위 제어**(런타임 계약 §7):
- `--roles FILE`로 repo별 두 supervisor의 주소·어댑터 토큰 파일을 받는다.
- `GET /v0/repos/{repo}/roles`: 두 역할의 상태.
- `POST /v0/repos/{repo}/stop`: 두 supervisor에 role 범위 `stop`을 **먼저 모두** 보낸다(한 역할로 다른 역할을 멈추지 않음, 한 역할을 기다리느라 다른 역할의 정지가 늦어지지 않음). 그다음 각자가 아무것도 실행하지 않을 때까지(합계 최대 30초) 기다리고, 역할마다 안전 종료 보고를 돌려준다. 정지 요청이 닿지 않았거나 200·202 밖으로 거부되면(예: 토큰 불일치) 기다리지 않고 바로 보고한다.
- `safe_shutdown_confirmed`는 다음을 모두 만족할 때만 참이다: 모든 역할이 응답했다, 실행 중인 회차가 없다, 체크포인트가 저장됐다, 활성 자식과 미확인 외부 요청이 없다고 보고했다.
- supervisor는 자식·외부 요청을 아직 추적하지 않아 `not_tracked`로 보고한다(0으로 쓰지 않음). 그래서 지금은 언제나 “미확인”이고, 이유가 목록으로 나온다.
- 범위 `roles:control`(서비스·사용자 자격만, 에이전트 거부, 자격의 repo 안에서만; repo 목록이 빈 자격은 어느 repo에도 닿지 않는다)이다. 연결할 수 없는 역할은 기다리지 않고 바로 “연결 불가”로 보고한다.
- OpenAPI에 두 끝점을 적었다.
- 시험: 가짜 supervisor로 정지·시간 안에 멈추지 않음·연결 불가·토큰 불일치, 코디네이터 API로 범위·에이전트·다른 repo 거부.
- start·reconnect를 코디네이터가 부르는 것은 배정과 함께 02-05에서 한다(제안, 수용 검토가 확인).

**supervisor 상태의 §7 항목**:
- `quota_group_id`: 설정값, 없으면 `unknown`.
- `provider_status_or_unknown`: 마지막 회차 stream의 마지막 `rate_limit_event`(status·overageStatus·isUsingOverage), 없으면 `unknown`.
- `last_actual_action_at`: 마지막 회차의 종료 시각.
- `restored_checkpoint_ref`: 서비스가 시작할 때 찾은 체크포인트(세션·단계·기준 회차·SHA-256, 읽을 수 없으면 `readable: false`).
- `capability_gaps`: 추적하지 않는 것(활성 자식, 미확인 외부 요청, `worktree_head`).
- 안전 종료 보고: 읽을 수 없는 체크포인트는 “저장되지 않음”이다. 체크포인트 파일에 `tracked`(세 항목 모두 false)를 남겨, 빈 목록이 관측값이 아님을 적는다.
