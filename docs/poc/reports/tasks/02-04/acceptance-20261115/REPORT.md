| §7 stop(repo 범위): 두 supervisor에 각각, 각 역할의 안전 종료 보고 | **부분 충족** | 모의 | 코디네이터가 두 역할에 정지를 보내고 보고를 모은다(진행 기록 8, 이 보고). 활성 자식·미확인 외부 요청을 추적하지 않아 안전 종료는 언제나 **미확인**으로 보고된다 |
| §7 status 항목 | **부분 충족** | 모의 | `quota_group_id`·`provider_status_or_unknown`·`last_actual_action_at`·`restored_checkpoint_ref`·`capability_gaps`를 보고한다(진행 기록 8). 한계는 아래와 같다(검토 fa39d86 M-a) |
| 실행 중 실제 정지 | 미실행(04-05 범위) | 문서 | 진행 기록 7 §5: 04-05(P05-R) 수용 범위로 판단, 결정안 있음 |

§7 status 항목의 한계(검토 fa39d86 M-a):
- `provider_status_or_unknown`은 계약의 값(`usage_limit`·`auth_or_billing`·`unknown`)으로 바꾸지 않고, 마지막 회차의 `rate_limit_event`를 그대로 보인다.
- 이 값과 `last_actual_action_at`은 끝난 회차 기준이라 실행 중에는 낡고, 재시작 뒤에는 `unknown`·null로 돌아간다.
- `quota_group_id`는 어느 설정에도 정해지지 않아 `unknown`이다.
