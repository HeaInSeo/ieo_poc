# 03-06 P22-B 검사 기대값

`POC-REQ-03-06 / 03-06.accept / poc-acceptance-v1.3.3@4`. 03-05와 02-02 수용 근거를 사용해 기본 실행 범위를 점검한다. [T04 수용](../../03-05/policy-images-20261119/ACCEPTANCE.md) · [02-02 평가](../../02-02/eval-20261112/REPORT.md) · [P22 계획](../../../../Console_Coordinator_PoC_Validation_Plan.md)

| 범위 | 기대 |
| --- | --- |
| 정상·재생성 32건 | Go와 Rust에 새 로컬 repo 2개씩, repo마다 개발·Guardrail을 분리한다. 각 역할이 언어별·통합 이미지에서 신생 컨테이너 2개로 같은 source SHA와 승인 프로파일을 실행한다. 모두 실제 검사 및 필수 시험 PASS, 기기록 role-state 0건이다. |
| 자료 및 역할 | 실제 문서 색인·언어 문서·프로파일과 검증 실행기 해시가 고정 입력과 일치한다. UID/GID 20001·20002, 네트워크 loopback-only, 유효 capability 0, no-new-privileges 활성이다. 호스트의 합성 자료 중 같은 역할 4종을 읽고 자신만의 상태를 쓴다. 상대 작업공간·세션·자격·승인 입력의 읽기와 쓰기 성공은 각각 0건이다. 승인 소스와 프로파일 쓰기 성공도 0건이다. |
| 필수 시험 건너뜀 2건 | Go `skip`와 Rust `ignored`는 도구 프로세스가 성공해도 실행기가 FAIL(1)을 반환한다. 작업공간 앞에 놓은 합성 도구 및 필수 시험을 빼는 환경 변수로 실행 경로를 바꿀 수 없다. |
| 필수 입력 누락 4건 | 프로파일 선택 누락 두 건은 인자 오류(2), 내장 색인·정책 파일 누락 두 건은 해시 검사 오류(1)다. |
| 비호환 이미지 2건 | Rust 파생에서 Go 또는 Go 파생에서 Rust를 요구하면 도구 없음(2)으로 거부한다. |

03-05의 OCI digest·이미지는 읽기 전용으로 재사용한다. 각 실행의 Podman graph/runroot와 입력은 로컬 `/tmp`에 분리하고, 코드·정책을 읽기 전용으로 바인드한다. 두 역할은 이번 시험에서 만든 합성 자격만 사용한다. 이미지를 삭제하고 다시 설치하는 빌드 재현, 전체 Kubernetes 권한, 실 CI 보호와 P22-C 비용 비교는 후속 검증 범위다. [고정 대상](inputs.json) · [역할 관측기](probe.py) · [시험 드라이버](run-p22.py)
