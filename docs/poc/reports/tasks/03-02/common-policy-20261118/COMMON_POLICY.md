# 공통 검사·역할·인계 기준 v0.1.0

적용 기준은 v1.3.3의 `POC-REQ-03-02 / poc-acceptance-v1.3.3@4 / 03-02.accept`다. [작성 계약](../../03-01/catalog-contract-20261118/CATALOG_CONTRACT.md)의 `CAT-ROLE@0.1.0`과 `CAT-RECOVERY@0.1.0`을 구체화한다. 이 문서는 새 대상의 정책 작성에 사용할 범용 기준이다. 실제 도구 명령, 권한과 배포·정지 조건은 대상의 승인된 배정 및 프로파일에서 읽는다.

## 테스트와 린트

| 확인 | 정책 | 남길 증거 |
| --- | --- | --- |
| 기준 고정 | 작업과 요구별로 적용 여부, 필수·보조 검사, 도구·버전·중요 옵션, 실행 위치·권한, 필수 결과와 실패 기대값을 제출 전에 확정한다. 후보 SHA 또는 시험 입력 digest를 기록한다. | 승인 프로파일 revision, 작업 범위, 입력과 도구 pin, 기대값의 작성 주체 |
| 테스트 | 정상 경로, 잘못된 입력이나 권한, 실패 뒤 복원 또는 상태 불변을 적용 범위에서 대조한다. 종료 0에 더해 필수 산출물·표식·검사 분모를 확인한다. | 실행 수, 종료 사유, stdout·stderr 및 산출물 digest, 양성·음성 기대와 실측 |
| 린트·형식 | 지정한 버전과 경고 실패 정책으로 검사한다. 검토할 파일을 변경하는 모드와 읽기 전용 확인 모드를 구분한다. 자동 교정 뒤에는 새 head를 검토·검사한다. | 대상 파일/패키지 범위, 옵션, 결과와 경고 정책, SHA |
| 실패·불충분 | 비0 종료, 신호, 시간 초과, 기동 실패는 실패다. 종료 0이라도 필수 증거가 비면 불충분이다. 고정한 실패 실험은 의도한 오류와 필수 표식이 정확히 일치할 때 시험이 통과한다. | 시도 ID와 실패 원인, 보존한 로그, 예상 오류와 일치 여부 |
| 비적용·건너뜀 | 사전 적용 조건에서 벗어난 항목만 사유와 근거를 붙여 비적용으로 둔다. 필수 검사 건너뜀, 취소, 실행 미확인, 결과 미확보는 요구 충족을 보류한다. | 프로파일 조항, 적용 판단, 실제 check/run 상태 |

런타임과 DB가 필요한 시험에는 고정 이미지, 대상에 따라 승인된 격리, 최소 자격, 시간 상한을 명시한다. 비용은 추정·실측·미계측을 구분하고 원래 회차와 교정/검토를 식별한다. Go/Rust별 도구·명령 비교는 03-03 범위다. [02-01 수집·판정 계약](../../02-01/collector-20261112/REPORT.md)

## 역할과 인계

| 역할 | 책임 | 인계 근거 |
| --- | --- | --- |
| 개발 | 배정된 작업 브랜치에서 수정하고 내부 검사·증거를 붙인다. 범위 변경과 승인 판단은 별도 담당자에게 넘긴다. 반려 뒤 교정에는 새 SHA와 처분 기록을 제출한다. | 배정 ID·세대·spec digest, repo/작업 ref·SHA, 검사 및 결과, 변경·미해결 목록 |
| Guardrail | 현재 head의 읽기 전용 스냅샷에서 승인 기준과 증거를 독립 대조한다. 필요한 재현은 승인된 격리 실행 경로에 의뢰한다. 개발 브랜치·대상 원본과 역할 자격의 변경 권한은 없다. | 검토자·역할, 정확한 대상 SHA·세대, 승인/반려, 위반 기준·재현 자료 |
| 코디네이터·운영 주체 | 배정과 evidence 정본을 대조한다. 미해결 반려·다른 SHA·누락 검사를 차단하고, 권한 있는 병합 주체가 승인 SHA를 조건으로 병합한다. 병합 뒤 그 SHA의 대상 브랜치 CI를 확인한다. | PR/head/base, check/run ID와 결과, 승인/병합 SHA, 다음 배정의 선행 충족 여부 |

검토 제출 때 내부 검사와 대상 SHA를 함께 고정한다. head나 검토 세대가 바뀌면 이전 검토는 그 시점의 근거로 보존하고, 새 head에 검토와 CI를 연결한다. 이 원칙은 브랜치 보호가 요구하는 GitHub 승인 숫자와 함께 적용한다. 역할의 실제 파일·자격·배정 권한은 환경별 계약에 따른다. [런타임 계약 §2·§4](../../01-02/runtime-contract-20261112/Runtime_Contract_v0.md) · [인계와 재개](../../../../DEV_AGENT_HANDOFF.md)

## 실패 뒤 재개와 보고

1. 제출 전 실패면 영향과 로그를 보존하고 승인된 범위에서만 교정한다. 재실행은 새 시도 ID에 이전 ID를 연결한다.
2. 응답 유실·부분 효과·상태 불일치가 있으면 동일 요청 ID의 결과, 장부, 외부 상태를 읽어 대조한다. 불확실성이 남으면 대기하고 재전송하지 않는다. 운영 복구 승인·재시도 예산은 해당 배정에 따른다.
3. 검토 반려나 최신 base 요구 때문에 후보가 바뀌면 바뀐 head를 재검토·재검사한다. 병합 뒤 main CI 실패는 병합 SHA로 기록하고 의존 작업의 수용을 보류한다.
4. 인계 시 현재 단계, 배정 세대, base/head, 검토·검사와 원본 링크, 남은 한도·미확정 외부 효과, 재개 조건과 다음 담당을 함께 넘긴다.

[고정 NPG 역할·응답 유실 후보](../../03-01/catalog-contract-20261118/sources.json)는 참고 입력이다. 이식 동작 및 실제 적용 효과는 P21/P23 및 해당 범위 검증에서 별도 확인한다.
