# 01-04 첫 세 probe · 실행 후 덧붙인 측정과 기록 교정

[PROBE_PLAN.md](PROBE_PLAN.md)는 실행 전 고정본(a321cd2, 측정 보강 93a44ad)을 그대로 둔다. 이 문서는 실행(2026-11-12 07:05~07:07Z) **뒤에** 더한 것만 모은다. 판정 기준(PROBE_PLAN §1~§3)은 바꾸지 않았다.

이전 head 0303f3e에서는 이 내용이 PROBE_PLAN §5로 고정본에 덧붙어 있었다. 독립 검토 [P3-5](reviews/review-pr12-0303f3e.md)에 따라 별도 문서로 옮겼다.

## 1. P3 계정 식별 출처 추가

- 계획한 관측 경로 `claude auth status --json`은 토큰 인증(`authMethod=oauth_token`)에서 계정·org 필드를 내지 않았다([P3.json](evidence/P3.json)의 `fields_present`).
- 그래서 결과를 본 뒤 식별 출처를 하나 더했다. 각 역할 CLI가 공급자에게서 받아 자기 설정 디렉터리에 저장한 policy-limits JWS의 클레임이다. 모델 요청은 쓰지 않았다.
- 증거: [P3-identity.json](evidence/P3-identity.json), 생성 스크립트 [identity_claims.py](../../../../../../probes/01-04/identity_claims.py). 값은 남기지 않고 형태(uuid 가림), SHA-256 앞 12자, 같음 여부만 남긴다.
- 출처 기록: 수집 시각, 원본 파일의 SHA-256 앞 12자·크기·mtime, 실행 명령.
- 서명: 두 문서 모두 ES256 서명이 `x5c` 리프 인증서로 **검증된다**(`openssl dgst`: Verified OK).
  - 두 문서는 서명·리프 인증서·`kid`가 서로 다르다. 각 역할이 따로 받은 문서라는 뜻이다.
  - 체인의 발급자는 `O = Anthropic, CN = Claude Code Signed Cache Issuing CA`다. 시스템 CA 저장소에서는 상위 발급자를 찾지 못한다(`unable to get local issuer certificate`). 그러니 이 검증은 “문서가 리프 키로 서명됐고 변조되지 않았다”까지만 보인다. 그 리프 키가 공급자 키라는 신뢰 사슬은 확인하지 못했다.
- 클레임 의미: PoC 개발 도구의 호스트 로그인(`~/.claude.json`의 `oauthAccount`)과 같은지만 대조했다. 값은 남기지 않았다. 호스트 로그인은 의미 해석에만 썼고, 역할 자격이나 런타임 입력으로 쓰지 않았다.
  - 두 역할 모두 `sub` = accountUuid, `aud` = organizationUuid였다.
  - `ws`는 둘 중 어느 것과도 같지 않다. 그래서 계정·org 식별 근거에서 뺀다.
  - 판정 근거는 `sub`(계정)와 `aud`(org)이고, 두 역할에서 같다.

## 3. 토큰 SHA-256 전체값 노출 처리 (P2-1)

- **원인.** 2d 검사는 컨테이너 안에서 해시를 비교하려고 대상 토큰의 SHA-256 전체를 명령 인자로 넘겼다. 하네스는 그 argv를 그대로 증거에 저장했다. 계획 §0의 “SHA-256 앞 12자 지문만 남긴다”를 어겼다.
- **교정.**
  - `P2.json`의 두 해시 전체값을 앞 12자 + `[sha256-truncated]`로 바꿨다. 이 파일에서 바꾼 것은 이 2곳뿐이다.
  - 하네스 `Ledger.scrub`가 토큰 해시 전체값도 같은 방식으로 가린다. P2 시험의 argv도 저장 전에 scrub를 거친다.
  - 저장소 작업 트리 전체를 다시 검사했다. 토큰 값과 해시 전체값 모두 0건이다.
- **남는 사실.**
  - 이전 커밋 0303f3e는 이미 공개 브랜치에 push됐다. 그 이력에는 해시 전체값이 남는다. 이력은 다시 쓰지 않는다. 사용자 결정 D11과 같은 원칙이고, 이 환경에서는 force push도 막혀 있다.
  - 위험 평가: SHA-256은 고엔트로피 토큰을 복원하는 데 쓸 수 없다. 공격자가 후보 토큰을 이미 가졌을 때 그것이 맞는지 확인하는 데만 쓸 수 있다.
  - 토큰 교체 여부는 자격 소유자인 사용자가 결정한다(F01). 이 문서는 교체를 요구하지 않는다. 사용자가 교체하면 새 토큰으로 다시 실행하지 않는 한 이번 판정 증거의 지문은 옛 토큰의 것으로 남는다.
