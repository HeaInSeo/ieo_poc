# 01-01 · 목표·필수 기능·선택적 방법의 범위표

기준선 v1.3.3 · 출처: 실행 장부, 실험 상세 §1~§5, 제공 설계 로그, U3 및 2026-11-12 리뷰.
고객 결과: 사용자가 승인된 스프린트를 입력하면 코디네이터가 개발·독립 검토·교정·착지·인수·보고를 증거로 이어 수행하고, 사용자는 현재 진척·일정 영향·결정 요청을 읽고 판단할 수 있다.

| 대상/책임 | 종료 목표·수용 범위 | 제외/별도 |
| --- | --- | --- |
| 논리 repo console-coordinator | 명세/권한/배정·사건 DB·claim/verified·DAG·outbox·상태 조회의 자체 코드/계약/실증 | 실제 repo URL은 01-02/01-04 바인딩 전 미확정. 논리 이름을 임의 GitHub repo 생성 지시로 쓰지 않음 |

명세 의미는 사용자 승인 목표/원본, 코드/검사 판정은 독립 Guardrail, 배정·전이·검증된 현황은 코디네이터가 소유한다. 변환기·개발 에이전트가 권한·외부 계약·승인 기준을 임의 재정의하지 않는다.
필수 검증 FAIL/INCONCLUSIVE는 미충족이다. 선택적 방법의 유효한 기각은 평가 종료일 수 있으나 기능 PASS는 아니다. 실제 실행·완료 검수는 각 행의 원본 수용 기준을 따른다.
공수/일정은 현재 미산정이며 근거 없는 처리 속도·완료일을 확정하지 않는다. 사용자 희망 기한·원 기준일과 후속 실측 예측을 구분한다.
