# 01-04 첫 세 probe 예산·집계·제어 규칙 (F03)

계획 v1.3.3-A1 · 01-03 run `staged-freeze-20261112` · 결정 근거 [D2](../../../../User_Decisions_2026-11-12_0103.md)
**실행 전 고정 문서다.** 01-04 실행 중 바꾸려면 새 revision과 사용자 결정이 필요하고, 바꾼 값을 최초 기준으로 소급하지 않는다.

## 1. 상한

| 항목 | 상한 | 측정 |
| --- | --- | --- |
| 모델 요청 시도 | **총 30회**(P1~P3 합) | §2의 “시도” 단위. 이 값은 시도 수의 상한이며 공급자 쪽 요청 수를 직접 센 값이 아니다 |
| 전체 벽시계 | **7,200초** | 첫 시도의 기동 시각부터. 각 시도 기동 전에 남은 시간을 확인하고, 남은 시간이 300초 미만이면 새 시도를 시작하지 않는다 |
| 시도당 시간 | **300초** | `timeout -k 10 300`로 프로세스를 끊는다. 초과 종료는 시도 1회로 센다 |
| 추가 API 지출 | **0** | API key를 쓰지 않는다. `--max-budget-usd`는 로컬 상한일 뿐이므로 통제 근거로 쓰지 않는다 |

01-04 전체(시험 repo·DB·수신기 포함)는 별도 상한 14,400초(F05)다. 여기서 정한 7,200초는 그 안의 P1~P3 몫이다.

## 2. 집계 단위

| 구분 | 정의 | 30회에 포함 |
| --- | --- | --- |
| **CLI 기동(모델 없음)** | `claude --version`, `--help`, `auth status`처럼 프롬프트를 보내지 않는 실행 | 아니다. 따로 세고 원본 로그를 남긴다 |
| **모델 요청 시도** | 프롬프트를 넣은 `claude -p` 프로세스 1개. 결과가 성공·오류·시간 초과·기동 실패 중 무엇이든 기동한 순간 1회로 센다 | 그렇다 |
| 동시 실행 1회 | 두 역할이 겹쳐 실행되면 시도 2회로 센다 | 그렇다(2회) |
| 수동 재시도 | 같은 목적이라도 다시 기동하면 새 시도 | 그렇다 |

**부모·자식.** 모든 시도는 `--tools ""`로 도구를 끈다. 따라서 하위 에이전트(자식)와 도구 반복은 구조상 생기지 않아야 한다. 실제로 생겼는지는 stream-json의 `parent_tool_use_id`가 있는 사건과 tool_use 사건 수로 확인한다. 생겼다면 그 시도를 “통제 실패”로 기록하고, 자식 사건을 부모 시도에 귀속한다.

**재시도.** 래퍼는 자동 재시도를 하지 않는다. CLI 내부 재시도와 공급자 쪽 요청 수는 **계측 불가**로 기록한다. 결과 사건에 `num_turns`·`usage`·비용 필드가 있으면 원본 그대로 보존하되, 그것을 공급자 요청 수의 완전한 계측이라고 주장하지 않는다. `--fallback-model`은 지정하지 않는다.

## 3. 시도별 원본 기록

시도마다 다음을 남긴다(비밀 값 제외).

- 시도 번호, probe ID, 역할, 기동·종료 시각(UTC), 종료 코드, 시간 초과 여부
- argv 전체, 전달한 환경 변수 **이름** 목록(§4.3 허용 목록), `CLAUDE_CONFIG_DIR`
- 자격의 Secret 이름·지문(SHA-256 앞 12자). 값은 남기지 않는다
- stdout(stream-json)·stderr 원본, 결과 사건의 session_id·usage·비용 필드, 한도·인증 오류 원문
- 누적 시도 수와 남은 벽시계

## 4. 상한 도달과 한도 신호

- 30회나 7,200초에 닿으면 즉시 멈춘다. 판정하지 못한 행은 판정표([probe_gate_table.json](probe_gate_table.json))의 관측 불가(P2는 미확인)로 기록한다.
- 공급자 사용량 한도나 rate limit 신호가 나오면 새 시도를 멈추고, 원문을 원본 증거로 남긴다. 재개는 F06(공급자 재개 시각 우선, 없으면 30분 뒤부터 30분 간격, 최대 10회)을 따르며 재개 시도도 30회 안에서 센다.
- 인증·과금 오류는 재시도하지 않고 사람 결정을 요청한다(런타임 계약 §7).

## 5. 배분(계획값, 상한 아님)

P1 8회 이내, P2 8회 이내, P3 10회 이내, 예비 4회. 앞 probe가 덜 쓰면 남은 수를 뒤로 넘길 수 있다. 합계 30회는 넘지 않는다.
