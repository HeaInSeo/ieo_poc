# 사람이 쓰는 스프린트 양식

v1.3.3 · 01-07 산출물 후보. 제품 변환기/API의 실제 구현·인수는 미실행이다.
사용자는 목표·산출물·판정·기한만 쓴다. digest·프로파일 ID는 쓰지 않는다.

| 필드 | 필수/선택 | 예시 / 작성 지침 |
| --- | --- | --- |
| 제목·repo·목표 | 필수 | NodeKit / 승인된 기존 백로그 한 작업의 결과. 실제 작업은 P36 전에 선정 |
| 작업 이름·산출물·완료 기준·검증 방법 | 필수 | “출력 오류 문구 교정 / 수정본·시험 로그 / 승인 요구와 일치 / 기존 검사와 실제 CLI 입력 대조”는 설명용 예시이며 실제 백로그가 아님 |
| 선행 작업 | 선택 | 위 양식의 이름 또는 이미 승인된 작업 ID; 없으면 [] |
| 범위 제외·결정 요청 | 선택 | 새 기능·납기 변경이 있으면 명시; 빈 값은 [] |
| 기한 상태 | 필수 | set(시각+시간대), none(기한 없음+이유), undecided(미확정+이유) |
| 작업별 예상 범위 expected_duration | 선택 | min_minutes/max_minutes와 evidence 원본 참조. 비교 가능한 과거 실측이 없으면 필드를 생략하고 미산정 |

작성은 사용자, 변환은 개발 에이전트/변환기, 의미·범위·수용 기준 대조는 별도 Guardrail, 접수/권한/참조 판정은 코디네이터가 맡는다. 변환기의 보충은 사용자 요구를 바꾸는 승인이 아니다.
사용자의 원문과 수정 이력을 남기고 누락·모호함을 임의로 채우지 않는다.

변환 순서:

1. 입력을 HumanSprintInput_v0.schema.json으로 검사한다. 사람이 쓰는 이름을 안정적인 task_id에 매핑하고 원 이름↔ID를 보존한다. 기존 ID를 재사용/충돌 검사하고 미정의 선행·순환을 거부한다.
2. 승인 repo·품질 프로파일과 대조해 항목 ID를 채운다. 승인 프로파일에 없는 완료 기준은 의미 검토로 돌린다. 변환기가 기준을 새로 승인하지 않는다.
3. 요구 출처·revision·권한·한도를 바인딩한다. 미확정이면 draft와 공백 목록을 반환하며 실행 가능 등록은 거부한다. 선택 필드의 생략은 요구가 없는 경우와 아직 모르는 경우를 구분한다.
4. 미산정 작업은 estimate.state=unestimated, range_seconds=null, reason과 evidence=[]로 직렬화한다. 실측이 있으면 expected_duration.min_minutes/max_minutes에 60을 곱해 measured·초 단위 min/max·evidence를 채운다. min≤max와 원본의 존재/비교 가능성을 별도 대조하고 근거가 부적합하면 필드 위치와 교정 내용을 반환한다.
5. 명세를 새 revision으로 만들고 정렬 키/공백 없는 UTF-8 JSON에서 digest 필드를 제외해 SHA-256을 계산한다. 원 입력·변환본·변환 검토·등록 응답을 연결한다.

거부 응답 예시(형식 예시이며 실제 API 실행 증거가 아님):

```json
{"code":"UNRESOLVED_PREREQUISITE","field":"tasks[1].after[0]","message":"‘검사 준비’라는 선행이 없습니다.","correction":"등록된 작업 이름/ID로 고치거나 새 작업을 먼저 추가하세요.","retryable_after_edit":true}
```

양식에서 작업 삭제·완료 기준 변경은 원 기준선을 보존한 변경 처분을 거친다. 요청하지 않은 기한/범위를 변환기가 정하지 않는다.
프로파일·digest가 들어간 JSON을 사용자가 직접 쓰게 한 시간을 사람용 작성 시간으로 측정하지 않는다.
