## 근거와 변경

사용자는 테스트 분류·회귀 테스트·린트 개선을 도그푸딩으로 수행할 수 있는지, 기존 계획에 명시돼 있는지 확인한 뒤 현재 계획 업데이트를 논의했다. 그 내용을 [DF-02 작업 문서](Dogfooding_Quality_Improvement_DF-02.md)에 구체화하고 검증 계획 §4·실행 장부의 스프린트 06 안내·개발 인계에 연결한다.

첫 DF-01, 06-01/P17의 수용 기준, 기존 03~05의 필수 검사 구축·검증, 주계획 73개·후속 12개 및 실제 진척은 유지한다. DF-02는 별도 추가 작업으로 등록할 후속 계획이며 현재는 실행 등록 전이다. 새 실험 PASS·구현 완료·모델 예산 승인을 기록하지 않는다.

## 무결성과 병합 순서

- A1·A2·원본 SHA256SUMS 및 과거 검산 결과를 보존한다. 변경한 전달 문서의 현재 해시는 [A4 개정 색인](Amendment_v1.3.3-A4.json)에 추가한다.
- 검산기는 수용 프로파일을 바꾸지 않는 문서 개정을 인식하되, 기존 분모·프로파일·명세 digest·문서 해시 대조는 유지한다.
- A3는 PR #27의 검토 중인 개정 번호다. 이 보완은 A3의 내용을 재작성하거나 검토 head를 바꾸지 않는다. A4 번호는 그 다음 개정 후보로 사용한다.
- 이 브랜치는 main `2c86f3da0c74c9d94140a0198a201fff566c6618`에서 분리한 검토안이다. PR #27 처리 전에는 병합하지 않는다. 그 처리 뒤 최신 main을 반영하고 검산기의 개정 적용 순서를 A1→A2→(병합된 A3)→A4로 대조해 검토·CI를 다시 확인한 후 기존 병합 절차를 따른다.
- 제품 런타임 코드·API·검사 기준·CI·진행 원장은 바꾸지 않는다. Notion·DB·모델 세션·예약 자동화에 쓰지 않는다.

## 실행 인계

코디네이터 개발 담당은 DF-01 검수 뒤 최신 코드에서 DF-02의 범위·중복을 확인하고 실행 명세·의미 검토·별도 예산을 갖춰 추가 작업으로 등록한다. 이 문서 변경을 현재 작업·S0·P26의 새 선행으로 사용하지 않는다.
