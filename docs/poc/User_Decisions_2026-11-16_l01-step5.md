# 사용자 결정 2026-11-16 · 배정 한도의 토큰·시간 정의(L01 정의, 02-05 단계 5)

사용자가 대화의 선택 질문에 답한 내용을 그대로 옮긴다. 질문은 02-05 단계 5(배정 수준 시간·토큰 한도 집행, [02-05 계획](reports/tasks/02-05/plan-20261115/PLAN.md) §3.2 단계 5, 이월 C7) 구현 중에 나왔다. 명세의 `limits.total_tokens`가 무엇을 세는지는 01-03 동결 항목 L01([단계 동결 보고](reports/tasks/01-03/staged-freeze-20261112/REPORT.md) §3)의 미결 부분이었다.

## 1. 답

| 질문 | 선택지 | 사용자 답 |
| --- | --- | --- |
| 명세 `limits.total_tokens`가 무엇을 셀까요? | (가) 과금 토큰 3항 input+output+cache_creation(cache_read 제외)을 배정 전체 세대에 합산 / (나) 네 항목 모두(cache_read 포함) / (다) L01을 열어 두고 단계 5는 시간 한도와 미계측 정지만 집행 | **(가) 과금 토큰 3항** |
| 배정 시간 한도 `elapsed_seconds`는 무엇을 셀까요? | (i) 배정의 모든 세대 회차 실행 시간 합 / (ii) 배정 발급 뒤 벽시계 경과 시간 | **(i) 회차 시간 합** |

답에 앞서 사용자는 “계속 진행해줘”라고 지시했다.

## 2. 반영

- **토큰 정의(L01의 정의 부분).** `total_tokens` = input + output + cache_creation 토큰의 합. cache_read는 세지 않는다. 사용자가 02-05 실제 회차 예산 (나)에서 승인한 “합산 토큰”([사용자 결정 2026-11-15](User_Decisions_2026-11-15_0205-x08.md) §2.1)과 같은 셈법이고, 02-05 단계 3의 회당 상한과 같다. 배정의 합계는 그 배정의 모든 세대 회차 몫(02-01 계측기, 재개는 누적 차분)의 합이다. 네 항목은 회차마다 모두 기록한다.
- **시간 정의.** `elapsed_seconds` = 그 배정의 모든 세대 회차 실행 시간의 합. 회차 사이의 대기 시간은 세지 않는다. 승인 예산의 “전체 시간”과 같은 셈법이다.
- **남는 것(L01의 값 부분).** 이 결정은 무엇을 세는지만 정한다. 한도 **값**은 정하지 않는다. 실제 sprint의 `total_tokens=null` draft와 등록 검사 `UNBOUND_DRAFT`는 그대로이고, 값의 동결(개발 제안 → 사용자 승인 → 독립 검토)은 L01에 남는다. 숫자를 새로 정하지 않는다(정책 “numeric_values”).
- **미계측.** 미계측 회차를 0으로 세지 않는다. 미계측 회차가 있으면 그 배정의 다음 전달을 멈춘다(계획 그대로).
- 이 결정은 실제 모델 호출, 예비 회차 사용, 추가 결제를 승인하지 않는다. 02-05 실제 회차는 기존 결정 (나)의 범위와 단계 8 전제 그대로다.
