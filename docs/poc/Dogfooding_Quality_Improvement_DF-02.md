# DF-02 · 테스트·린트 품질 개선 도그푸딩 계획

상태: 계획 보완안 v0.1 · 2026-11-13 KST · 구현·실행 미착수 · 기존 73/12 집계 밖

## 먼저 읽을 내용

**완성되면:** 검증된 코디네이터가 자기 저장소의 테스트·린트 개선을 배정하고, 개발 에이전트의 변경을 독립 검토와 보호된 CI로 확인해 검사 종류·실행 범위·누락 여부가 드러나는 결과를 남긴다.

첫 자기 개발 과제 DF-01(보고의 문서 버전·SHA 표시)은 그대로 수행한다. 그 뒤 DF-02로 품질 개선 한 건을 수행한다. 이번 보완은 그 후속 과제와 실행 조건을 명시하는 문서 변경이다. 기존 기능의 필수 검증을 도그푸딩 이후로 미루는 결정이 아니다.

## 수행 목표와 산출물

**DF-02의 최초 범위는 자기 repo의 검사 결과를 종류별로 구분하고, 필수 검사의 실패·미실행을 숨기지 않는 품질 개선 한 건이다.** 기능 구현, 이를 지키는 회귀 테스트, 해당 범위의 린트 실행을 같은 과제로 묶는다. 테스트 수나 세부 판정 수를 별도 완료 작업 수로 세지 않는다.

| 산출물 | 완료 시 얻는 결과·재사용 범위 |
| --- | --- |
| 검사 목록·분류 매핑 | 승인된 검사 프로파일의 검사 ID·버전·명령·필수 여부를 형식/린트/단위/통합/계약/재생/런타임 등 실제 입증 범위에 연결 |
| 검사 결과 요약 | 기존 실행 기록과 원본 로그를 참조하는 JSON/Markdown 요약. 대상 SHA, 프로파일 버전, 검사별 실행/실패/건너뜀/미실행·미확인과 근거를 확인할 수 있음 |
| 회귀 테스트 | 아래 정상·실패·누락·0건·건너뜀 경계를 재현. 기존 시험·fixture가 같은 조건을 입증하면 재사용하고 부족분만 보강 |
| 린트 연결 | 해당 코드·fixture 변경에 승인된 fmt·clippy 등 기존 명령을 적용. 이미 있는 린터나 실행기를 새로 만들지 않음 |
| 도그푸딩 증거 | 고정 실행본의 배정 → 실제 개발 → 독립 검토 → 필요한 교정 → 현재 SHA의 필수 CI → 결과 보고를 같은 작업에 연결 |

명령 이름만으로 세부 시험 종류를 추측하지 않는다. 예를 들어 하나의 `cargo test`가 여러 범주를 포함하면 실제 보고·fixture로 입증한 범위를 표시하고, 구분할 수 없는 세부 범주는 미확인으로 둔다. 하나의 실행을 여러 범주에 연결하더라도 시험 수·비용·완료 수를 중복 합산하지 않는다. 새 분류는 기존 증거에 소급해 관측 사실을 추가하지 않는다.

기존 `evidence-record/v0` 스키마는 `additionalProperties: false`이므로 임의 필드를 덧붙이지 않는다. 최초 범위는 별도 요약으로 기존 기록을 참조한다. 원래 기록 형식을 바꿀 필요가 생기면 계약·호환성 검토를 먼저 분리한다.

## 입력별 수용 판정

실행 전에 독립 담당이 승인된 검사 목록과 기대 결과를 고정한다. 새 코드가 내는 출력에 맞춰 사후 기대값을 만들지 않는다.

| 판정 | 입력·조건 | 기대 결과와 실패 조건 |
| --- | --- | --- |
| Q1 정상·현재 후보 | 승인된 프로파일과 현재 후보 SHA의 실제 실행 기록 | 필수 항목의 종류·실행 상태·증거가 맞는다. 요약 성공만으로 코드 검수 완료나 승격을 주장하지 않는다 |
| Q2 린트·시험 실패 | 필수 린트 또는 시험이 실제로 실패하는 대조 입력 | 실패가 요약과 완료 판정에 전달된다. 종료 코드나 표식만 바꿔 정상으로 표시하면 실패 |
| Q3 필수 검사 누락 | 필수 항목의 실행 기록 또는 필수 결과 산출물이 없음 | 미실행/미확인과 이유를 남기고 완료로 처리하지 않는다 |
| Q4 0건의 의미 | 테스트 0건과 린트 경고 0건 | 해당 프로파일이 1건 이상 실행을 요구하는 테스트의 0건은 차단한다. 정상 실행한 린트의 경고 0건은 성공으로 구분한다. 개수 미측정은 0건으로 바꾸지 않는다 |
| Q5 건너뜀·비적용 | 사전 승인된 비적용/건너뜀, 필수 항목의 무단 건너뜀 | 승인된 범위와 사유만 비적용으로 표시한다. 필수 항목의 무단 건너뜀을 통과로 세지 않는다 |
| Q6 증거 버전 | 이전 SHA·다른 프로파일 결과를 현재 결과처럼 제시 | 기존 02·05의 검증 경로로 거부하고 해당 버전 원본은 보존한다. 현재 후보의 검증으로 소비되면 실패 |

03-07/05-02의 전체 거짓 성공 실험을 이 과제에서 새로 복제하지 않는다. 이번 변경이 영향을 주는 경계만 시험하고, 같은 버전·범위의 기존 결과를 재사용한 경우 출처와 한계를 표시한다. 성능·보안·부하·UI 등 모든 테스트 종류를 모든 작업의 필수 검사로 추가하는 과제도 아니다.

## 착수 조건과 진행 순서

1. **기본 기능의 검증은 계속한다.** 02~05와 현재 추가 작업은 기존 계획을 따른다. DF-02를 S0·DF-01·X-01/X-02·P26·운영 전환의 새 선행으로 넣지 않는다.
2. **DF-01/06-01을 검수한다.** 고정된 실행본과 보호된 외부 검증 경로가 준비된 뒤 DF-02를 배정한다. 후보를 승격해야 진행할 경우 S2/P18의 검증된 전환·복귀 절차를 사용한다.
3. **해당 검사 자료만 준비한다.** 사용할 종류·명령·필수 여부는 03-02~03-04의 해당 범위 또는 이미 승인된 최소 프로파일로 확정한다. 공통 이미지·카탈로그를 실제 사용할 때만 해당 03-06/03-07·P23-COMMON 선행을 추가한다. Go 전체 준비를 Rust 자기 repo의 일괄 선행으로 삼지 않는다.
4. **실행 입력을 동결한다.** 최신 기준 SHA, 남은 코드 공백, 수정 경로, 기대 결과, 검사 프로파일·버전, 역할 자격·작업 범위, 예산·시간·검토/교정 한도를 명세에 바인딩하고 독립 의미 검토를 받는다.
5. **별도 작업공간·브랜치에서 수행한다.** 이미 검증된 현재 실행본이 후보의 개발·독립 검토를 조율한다. 새 실행본의 개발을 위해 현재 실행본의 배정 권한이나 검사 기준을 약화하지 않는다. GitHub 검토·CI·병합·main CI는 기존 규칙을 따른다.
6. **증거를 대조하고 결과를 기록한다.** 계획 문서·PR 생성·CI 실행만으로 완료를 올리지 않는다. 실제 코드 변경과 Q1~Q6의 해당 증거, 독립 검토, 현재 SHA의 CI, 보고 수신을 연결한다. 기존 DF-01의 중단/재개 실험을 별도 이유 없이 전부 반복하지 않는다. 후보 승격은 완료 보고와 별도 사건이다.

테스트·린트 정책 자체를 변경하는 회차에는 정책 제안자와 승인 주체를 구분한다. 개발 에이전트가 자기 통과를 위해 필수 항목·기대값·판정기를 약화하거나 새 후보가 스스로 승인·승격하는 경로는 허용하지 않는다. 기존 검사 기준이 불합리하면 근거와 별도 정책 변경 절차를 사용한다.

## 물량·일정·진행률

- 물량은 **품질 개선 도그푸딩 한 건**이다. 분류·구현·회귀·린트·독립 검토는 그 한 건의 인수 요소다. 이후 확인된 새로운 회귀 테스트나 린트 개선은 원인과 소비자가 있는 별도 과제로 선정한다.
- 공수·착수일·종료일은 **미산정**이다. 코드 기준에서는 재사용 가능한 실행 기록·CI가 있지만, 착수 시점의 구현과 단위/통합 결과 분류 경계를 다시 확인해야 한다. 남은 변경·검증·검토/교정·외부 대기를 분리한 뒤 예측한다. 기존 전체 테스트 수를 시간으로 환산하지 않는다.
- 기존 주계획 73개·조건부 후속 12개·P17의 분모와 수용 기준은 바꾸지 않는다. DF-02를 06-01의 두 번째 필수 완료 조건이나 기존 12개 후속 중 하나로 몰래 넣지 않는다.
- 실행 등록 시 별도 추가 작업으로 추적하고, 계획/등록/구현/실험 검수/실제 승격을 나눠 기록한다. 지금은 계획 보완안이며 완료 가산은 0이다.
- DF-02의 실제 모델 실행 예산은 **미승인**이다. 01-04·02-04·X-02 또는 EARLY-01의 예산을 전용하지 않는다. 담당자가 부모·자식·개발·실패·검토를 포함한 범위와 산정 방식을 먼저 제시한다.
- 이 계획 변경은 실행 중인 모델 세션·Notion 원본·DB·서버 설정·예약 자동화·PR #27의 브랜치를 변경하지 않는다. A3는 PR #27에 남겨 두고, 문서 보완의 무결성은 [A4 개정 기록](Amendment_v1.3.3-A4.md)에 연결한다. PR #27 병합 후 최신 main을 반영했으며, A1→A2→A3→A4 적용 순서·필수 CI와 통합 변경 검토를 확인한 뒤 기존 병합 절차를 따른다.

## 독립 검토와 다음 인계

이 보완안은 기존 DF-01과 테스트·린트 계획을 잇는 변경 범위만 검토한다. 전체 PoC의 재검수나 실제 실행 인수로 확대하지 않는다. 문서 검산·별도 검토의 원문과 처분은 [계획 검토 기록](reports/planning/df-02-20261113/REVIEW.md)에 남긴다.

다음 담당은 코디네이터 개발 담당이다. 이 문서의 준비·착수 조건에 도달하면 최신 구현과 중복을 대조하고, DF-02를 실행 가능한 명세와 별도 추가 작업으로 옮긴다. 현재 주계획의 독립 작업과 X-01/X-02의 남은 작업은 계속 진행한다.
