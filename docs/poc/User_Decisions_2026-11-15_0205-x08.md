## 2. 반영

### 2.1 02-05

- **F4 승인(계획 §2.1 (다)).** GitHub 검토의 독립성은 숫자 GitHub user id로 대조한다. “변경 작성자”는 PR 작성자 id와 그 repo 개발 역할에 등록된 GitHub 신원(App 봇 id 포함)의 집합이다. 검토자 id가 이 집합에 있으면 독립 검토가 아니다. 개발·Guardrail은 서로 다른 GitHub 신원을 쓴다. 판정 정책 G3의 새 버전은 실제 GitHub 수집을 연결하는 작업(1b: 04-07·05-01~05-03·EARLY-01)에서 만든다. **02-05에서는 코드를 바꾸지 않는다.**
- **S1 확인.** 판정 정책 0.6.0을 유지한다(G1 `outputs` 비교를 좁히지 않는다).
- **바로 착수.** 02-05 구현 단계 1~7(모델 호출 없음)을 시작한다. 계획이 개발자 결정으로 보고한 N5·U2·T1·C2도 그대로 진행한다. U2로 X-01 시험 한 건의 첫 거부 코드가 409 `IMPORT_GATED`에서 422 `UNBOUND_DRAFT`로 바뀐다(거부 집합은 같음). 단계 1 PR에 적는다.
- **실제 회차 예산 (나).** 계획 §4.3의 표 그대로다.

### 2.2 X-08

- **Q-3 (가).** start는 설정 변조를 탐지하지 않는다. start는 설정을 정리하므로 빠지는 것은 변조의 보고뿐이다. 계약의 알려진 한계로 기록한다. 코드는 바꾸지 않는다.
- **손상·객체가 아닌 대기 파일: 재개 거절.** 새 탐지 없이 대기 변조 파일을 읽을 수 없거나 객체가 아니면 재개하지 않고 사람의 대조를 요구한다(닫힌 쪽). 코드와 시험으로 반영한다.
- **유지한 동작 확정.** 더 오래된 대기 탐지가 앞선다(Q-2). 3초 잠금 대기를 유지한다(L-c3-2). 장부 이동은 진단 문구만 준다(P4).
- 이 반영과 독립 검토·병합 뒤 X-08을 검수한다. X-08 검수 완료 전에는 X-02와 모든 실제 모델 호출을 하지 않는다.
