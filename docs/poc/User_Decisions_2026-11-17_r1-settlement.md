## 2. 조건(사용자 지시 그대로 옮김)

**승인 범위.** 독립 검산, 정산 형식 구현, 시험 보강, 재개 문서·스크립트 작성과 각 PR의 검토·병합·main CI 확인까지다. 실제 장부 정산 반영, 서버 재시작·교체, R1b·R2·G1 실행은 완성된 재개안을 보고 별도로 승인한다.

### 2.1 정산 수치를 먼저 독립 검증
별도 검토자가 승인된 접근 경로로 보존 원본 또는 해시가 같은 사본을 확인하고, 작성자의 대조 결과와 독립적으로 사용량을 재계산한다. 확인 대상은 세션·시도 일치, 같은 message.id의 중복 제거, 네 가지 토큰 항목, API 요청 기록 수, cost-state 전후 항목과 시각이다. 검산 대상 값은 billable 1,543과 cache_read 3,223이며, 아직 확정값으로 취급하지 않는다. 검산으로 확인되는 범위와 클라이언트에 기록되지 않은 요청의 불확실성을 구분한다. 근거가 부족하면 미계측을 유지하고 필요한 결정을 보고한다. 접근이 막히면 거부 사유와 최소한의 확인 방법을 제시하고, 가능한 구현·시험 준비는 계속 진행한다.

### 2.2 정산과 실행 결과를 분리
기존 R1의 실패, 가드 중단, 미계측 원본과 사용량 기록은 보존한다. 승인된 정산은 출처를 `transcript_exit_accounting`으로 명시한 별도 기록으로 추가한다. 정산 기록에는 대상 시도, 근거 사본·해시, 검증 결과, 적용 정책과 사용자 결정 참조를 남긴다. 장부를 읽을 때 재검증하고, 변조·중복·다른 시도 적용은 거부한다. R1 회차와 사용량을 이중 집계하지 않는다. 정산으로 예산 계산이 가능해져도 R1의 실패가 성공으로 바뀌지는 않는다. 관측 하한 1,429를 총사용량으로 사용하지 않는다.

### 2.3 (A)와 L-4 해석은 이번 R1에 한정
- 새 정책으로 s8-r1의 경고 신호를 재평가하되, 당시 정책에 따른 중단 이력은 보존한다.
- 독립 검증과 정산 승인을 전제로, 이번 가드 중단 때문에 발생한 “결과 사건 없음”을 사람의 예비 승인으로 해제할 수 있도록 한다.

이 처리는 이번 s8-r1에 한정한 특례다. 다른 미계측 회차, 실제 한도 거부, 추가과금 신호, 시간·토큰 초과에는 확대하지 않는다. 재개 시 집계는 기존 실패 R1 + 예비 R1b + R2 + G1 = 전체 4회다. 기존 역할별·전체 시간과 토큰 상한, 추가 청구 USD 0은 유지한다. R1b는 사람 자격으로 예비 표식을 붙여 새 세션으로 시작하고, R2는 그 세션을 재개한다. 추가 예비와 자동 재시도는 없다.

### 2.4 시험과 검토
정산 근거 변조·중복·잘못된 시도·자료 불충분을 거부하는 시험과, 이번 특례가 다른 중단 사유를 해제하지 못하는 시험을 포함한다. 남은 Low L-1~L-3(PR #89 검토 91e87ce) 시험 공백도 관련 PR에서 보강한다.

### 2.5 최종 재개안
독립 검산 결과, 정산 후보 기록, 남은 예산, 이번 특례의 적용 범위, 코드 SHA, 서버·역할 컨테이너 교체와 되돌리기, 허용 규칙 변경, 관측 유효 기간, 사용자 실행 명령을 묶어서 제시한다. 준비와 검토·병합·CI 확인은 추가 진행 지시 없이 잇고, 실제 정산 반영과 운영 변경·모델 호출 직전에 최종 묶음 승인을 요청한다.
