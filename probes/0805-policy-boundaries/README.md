# 08-05 / P11 · 격리 배포·앱 권한 대조

전용 공개 표준 Ubuntu 24.04 amd64 VM에 [08-02의 고정 도구와 커널 조건](../0802-cluster-baseline/README.md)을 준비한다. `bash probes/0805-policy-boundaries/run-lab.sh "$(mktemp -d)/run"`은 기존 08-02 코드로 초기 상태를 확인하고 별도 P11 검사를 수행한다. 같은 격리 VM의 보호된 kubeconfig, `kind-ieo-0802` 컨텍스트 및 Pod IPv4를 사용한다. 08-02의 생성 전 트랩이 P11 뒤에도 동작하며, 전용 노드 0개를 판정에 포함한다.

## 실행 전 판정 기준

| 범위 | 사례와 기대값 |
| --- | --- |
| PSA | Restricted v1.35의 두 실제 역할 Pod가 Ready·재시작 0이며 각 SA·UID가 일치한다. 개발·Guardrail 각각 정상 명세는 서버 dry-run 수용, `allowPrivilegeEscalation` 한 필드 변형은 Restricted 정책의 해당 필드 오류로 거부. 실제 저장된 변형과 dry-run 객체는 0개다. |
| 역할별 NetworkPolicy | 두 역할 × 두 역할 수신기 × 초기·집행·복귀의 12건. 초기와 복귀의 4건씩 모두 성공. 집행 상태는 각 역할의 자기 수신기 2건 성공, 서로의 수신기 2건은 2초 TCP 제한에서 실패·수락 0건. 같은 이름의 egress 정책을 교체하고 변경 뒤 12초 후 표본을 실행한다. 각 사례의 클라이언트 합성 ID와 수신기 원본에 생긴 행을 대조한다. |
| 앱 | 초기 네트워크 정책 복귀 후 별도 합성 HTTP 객체 두 개. 각 역할의 상대 객체 읽기·쓰기 네 건은 403과 구조화된 거부 응답만 반환한다. 상대 객체는 원 소유자가 전후 조회해 내용이 동일하다. 역할별 자기 객체 쓰기와 읽기는 정상 처리된다. 12건 요청의 서버 감사 원본과 클라이언트 결과가 일치한다. |
| 파일·자격 | P07의 역할별 거부 원본이 선행 근거다. 원장에 해당 회차가 없으므로 미검증으로 유지한다. 합성 앱 토큰은 이 작업의 요청 주체 구분에만 쓰이고 실제 제품 자격 증거에 포함되지 않는다. |

P11의 합성 앱 결과는 이 테스트 구현의 읽기·쓰기 경계에 귀속된다. 작업 범위의 네트워크는 전용 CNI와 수신기 Pod TCP 18080이다. 파일 격리와 실제 제품 계정·제품 인가를 별도로 검증해야 08-05 전체를 수용할 수 있다. 실제 운영, 레지스트리 쓰기, 모델 호출, 신규 과금은 이 절차에 포함하지 않는다.
